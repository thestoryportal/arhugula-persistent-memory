== Design decisions already made (MAESTRO) ==
The freeze is prescriptive, not observational. The guard will launch ONLY what P lists, exactly as P lists it, and refuse everything else. So every launch path I2 records, plus the two V5 names, ends in exactly one of two places:
- P.profiles: a complete LaunchProfile (scope SCIENCE) in J2's shape with three changes codexr2m is adding: (a) BindingDeclaration.source_record may be "ScienceLaunchContextRecord"; (b) InvocationProfile has a required `dependencies` array of {"path": ..., "sha256": ...}; (c) EnvironmentEntry.value may be a BindingPlaceholder. Every argv token and environment value is a literal or {"$bind":"<name>"}; nothing is variable-arity.
- P.not_admitted: {entrypoint path, sha256, reason, citation path:line, what would admit it}. Use this when a path cannot be made fully literal from source: for example argv appended at variable arity (tools/mathlab_cpu_runner.py:63,67), a uv-resolved interpreter or package set with no lock file you can hash, or a payload chosen at run time (replay DEST). Not admitted means the guard refuses it; that is closed, not OPEN.
Binding suppliers: every bound value comes from the ScienceLaunchContextRecord that the science launcher exclusive-creates before spawn (codexr2m defines it): launch_id from /launch_id, every other name from /values/<name>. Declare each in the profile's bindings. Do not write "no record supplies this today".
Closed environments: each InvocationProfile.environment is the exact environment the guard passes; nothing is inherited. Where a wrapper copies os.environ (G:69, experiments/track_c/c10w_oracle_step0.py:299, tools/mathlab_cpu_runner.py:68), record that it then copies exactly this closed set, with the path:line. List every variable the code reads that must be set, with its literal or bound value; PATH is literal.
Identities: each invocation's executable_path is the realpath and executable_sha256 its shasum. dependencies lists every repo-local imported module and the lock/manifest files that fix third-party versions (for .venv launches: uv.lock and pyproject.toml), each with path and sha256 you computed. Each child process gets a ChildProfile with the same completeness (for example /usr/bin/vm_stat, tools/mathlab_runtime.py:85).
The two V5 names (experiments/track_c/autoresearch_c10/replay_exp2/tokenizer_precheck.py:88–95 and experiments/track_c/c10u_mint2_wordlist.py:111,120,149) each get a profile or a not_admitted row.

You may also run `ls` on ~/Library/LaunchAgents, /Library/LaunchAgents and /Library/LaunchDaemons, `plutil -p` on any plist there, and `crontab -l`.
