## D14 (answers R1 / V10 F1): a branch chosen by data the admission reads is reachable unless code that runs before the spawn excludes it

**What MAESTRO checked in the unchanged source (re-read 2026-10-11 20:07Z):**
- `tools/c10w_p2_gate.py:100–105`. The first P2 stage builds its certificate in code with `phase="P2"` (:103). Every other stage, including `p2-eval`, loads `R.latest_directory("p2") / "preflight.json"` from disk (:101, :104) and passes it to `T.require_training_preflight` (:105). That code never checks `proof["phase"]`.
- `experiments/track_c/c10w_oracle_train.py:51–66` checks provenance and evidence, then sends the certificate to the `verify-preflight` child (:65–66). It does not check the phase either.
- `experiments/track_c/c10w_oracle_read.py:583–588`: `verify_preflight_certificate` calls `authorized_phase_entry` whenever the certificate's own phase is P2 or P3 (:588). In `authorized_phase_entry` (:531–539), a P3 certificate calls `replication_for` (:538). That reaches `require_untracked_adapter` (:550), then `adapter_is_tracked` (:139–140), then `adapter_is_tracked` (:130–135), which spawns `/usr/bin/git ls-files --error-unmatch` (:133).
- K7 filters process sites by the stage taken from argv (K7:2358–2364). The P5 note at P5:435424 claims the branch "does not run in current P2 admissions". V10 F1 shows that the argv stage does not decide this branch; the certificate's phase does.

**Rule.**
1. **Reachability follows what the code checks, not what the stage name implies.** A process-start site behind a branch chosen by data the admission reads (a loaded file, a certificate field, an environment value) is reachable from that admission. It stays reachable unless code that is pinned and reached first, before the spawn, forces the branch. Typical examples are an assertion or a constant assignment. A stage name, an argv value, a file's usual contents, or a branch that "does not run in current admissions" is not such an exclusion. Every exclusion the freeze relies on must cite the enforcing line.
2. **Apply it to the verifier's P3 branch.** For every admission that loads its certificate from disk (every P2 stage except the first, and `p2-eval`), the route verify-preflight → `authorized_phase_entry` → `replication_for` → `require_untracked_adapter` → `git ls-files` yields an `ADMISSION_HELPER` / C:115 occurrence of the Git recipe without A1 authority. Science-origin uses keep their A1 labels (D13 item 1). When the same admission already reaches the same Git recipe by another admission route (for example `p2-eval` through `R.phase_trains`, gate :128), it remains one admission-origin occurrence that cites every admission route reaching it. Never merge it with a science-origin occurrence.
3. **The first stage's exclusion is recorded with its enforcing line.** The first P2 stage's certificate has `phase="P2"` set at gate :103 before the verifier is spawned, so the P3 branch is excluded there. The freeze records this exclusion with the gate :103 citation. K7 checks that pin: the line hash or text must match the pinned source.
4. **K7 models data-selected sites separately from argv-selected sites.** Each recorded process site states what selects its branch: `argv_stage`, `loaded_data`, or `unconditional`. For a `loaded_data` site, K7 includes the occurrence for every admission that loads the controlling data, and excludes it only where the site records a pinned enforcing exclusion (item 3). K7 must never filter a `loaded_data` site by the argv stage alone.
5. **Absence claims are corrected.** Remove or rewrite every statement in F9, P6 and I8 that says this branch does not run in current P2 admissions (P5:435424 and any copy in F8/I7). The D13 item 3 limit still applies: the recorded trace is reproducible and complete only for its recorded queries. It is not a complete call graph.
6. **Composition refusal is unchanged (D10).** Every composition whose admission spawns any helper stays refused with `NOT_ADMITTED_ADMISSION_HELPER_UNREGISTERED:`. The new occurrences add reasons, never subtract.
