## 1. LARQL (Apache-2.0, Rust; created 2026-03-27; 1,162★; **1,941 commits since 2026-06-01**; releases v0.1.0/v0.1.1 Jul 2026 → `vindex-v0.8.0` 2026-09-02)

**What it is now.** "Execute, query and study a model as an artifact." "LARQL is the reference implementation of VINDEX3 and a research system for model execution, representation and evidence." "The graph-database thesis remains: the model itself is the object being queried, rather than a separate database of extracted facts." Verbs: Encode · Run · Represent · Observe · Intervene · Query. Container: `vindex plan|encode <HF checkpoint> → model.vindex3`, `larql vindex3 exec|observe`, `larql serve model.vindex3`. VINDEX3 "reached full LQL parity with VINDEX2 … VINDEX3 is the candidate primary generation; VINDEX2 is the compatibility generation" (default extraction still V2).

**GGUF.** Input to V2 only (`extract`: "safetensors/GGUF/MLX → queryable"; `convert`: "GGUF ↔ vindex"); for V3 "GGUF sources refuse by name rather than transcoding on the way in". **GGUF export landed 2026-08-31** (PR #363: "the first emitted hero file, verified before any runtime sees it"; "stream tensor payloads, so a 20 GB export is expressible"; "the qwen35 metadata table"). LQL `COMPILE … INTO MODEL <path> [FORMAT safetensors|gguf]`: "If the patch overlay contains INSERT operations, MEMIT closed-form weight editing is used to bake the inserted facts into W_down at the install layer(s). The output is a standard safetensors / gguf file with no vindex dependency at inference time."

**Apple silicon.** "the default GPU feature uses Metal on macOS"; positioning doc: "Apple Silicon Metal ✅ (88 tok/s Gemma 3 4B)" vs Ollama ~103; credibility rule "LARQL must be within 10% of llama.cpp / ollama … before any '+N% from technique X' claim is published". 123 commit subjects since June mention Metal.

**In-weight memory — a second MEMIT implementation.** `crates/larql-inference/src/forward/memit.rs` (554 lines; header: "MEMIT closed-form weight editing — compile vindex patches into W_down. Implements the core MEMIT algorithm from Meng et al. (2022–2023), adapted for GatedFFN architectures (Gemma, Llama, etc.): ΔW = (V* − W·K*)·(K*ᵀC⁻¹K* + λI)⁻¹·K*ᵀ·C⁻¹ … so installed facts route through rarely-used directions — invisible to normal text. Validated in Python: 200/200 (100%) at N=200 with multi-layer distribution across L8-L12 on v11 TinyStories 115M"), plus `engine/memit_store.rs`, `executor/memit_persist.rs`, `lifecycle/compile/bake/memit_apply.rs`, bench `memit_solve.rs`. **A `MemitFact` is `prompt_tokens` + one `target_token_id` (single-token targets)**; covariance from a built-in `COVARIANCE_PROMPTS` list ("Python reference used ~2000 prompts with ~14K total positions"); solve by Cholesky in f64; files last touched 2026-05-10; **no commit subject since June mentions MEMIT** (stable, not under change). LQL memory tiers: `INSERT` (mode `KNN` default, `COMPOSE` FFN-overlay) → `COMPACT MINOR` ("Promote every L0 (KNN) entry into L1 (arch-A compose edges)") → `COMPACT MAJOR [FULL] [WITH LAMBDA]` ("Promote L1 compose edges to L2 MEMIT-decomposed (key, down) pairs… LAMBDA is the MEMIT ridge (default 1e-3)"); `SHOW COMPACT STATUS` ("L2 is only reported when hidden_dim ≥ 1024 (MEMIT requirement)"); `BEGIN/SAVE/APPLY/REMOVE PATCH` overlays ("Base vindexes are immutable: mutations use overlays and compilation produces a new artifact"). Positioning table: "MEMIT / KNN weight edits ✅ LARQL ❌ Ollama ❌ vLLM ❌ llama.cpp". ROADMAP (2026-05-28): "'query, edit, and interpret the model like a graph database' — DESCRIBE, INSERT INTO EDGES, walk, MEMIT / AOT compilation — is a genuine moat with no competitor"; exit criterion "edits verifiable via TRACE parity and reversible."

**the-mechanism → LARQL.** ROADMAP_STATUS (2026-06-07): "The `chris-experiments/fleet` native-store arc (E10–E17) + `videos/the-mechanism` build story ported into the Query/Edit/Interpret track" → FR1/FR2/FR3 fleet routing ("the entity key is real & answer-leak-free at L24-26 (L26 top1 0.89/top5 0.95)"; "relation synonym-gen 1.00 at every layer L6-L26"; `INFER … ROUTE VERIFY [FALLBACK] [TOPK n]`). `docs/observatory.md` §20 "Visual lineage: the-mechanism".

**Observe/Intervene (new since June).** `larql vindex3 observe --record run.jsonl`, `--heads`, `--intervene` ("declared carrier changes and in-kernel CPU softmax head counterfactuals"); "A projected contribution is not a counterfactual." The Sept–Oct stream is pre-registered research arcs (`continuation-codec-1/2/3`, `measure-plan-3`, `auto-rep-landscape-1`, `auto-rep-prior-1`) plus Qwen3.5/Qwen3-VL/Qwen-MoE plumbing and Metal kernels; Qwen2 2026-09-26 "feat(vindex3): Qwen2 Q/K/V-only attention bias and the gated share…".

**Bearing on the program (I-INFER where marked).**
- **Serving spine (S).** LARQL is not a GGUF runtime; the local path would be HF safetensors → `vindex encode` (V3, Metal) or GGUF → V2 `extract`. Breaking changes since June: V3 container/CLI, `--generation v3`, GGUF refused into V3, plugin ABI, tag scheme. The program's B3 spine (edit in the vendored engine → GGUF → llama.cpp) is unaffected, but a Metal-native alternative now exists with the 10 %-of-llama.cpp rule as its own gate.
- **A cross-check engine (Q5/Q7).** The Rust MEMIT uses the same closed form, a Cholesky f64 solve, a built-in covariance prompt set, and λ default 1e-3; it reports 200/200 at N = 200 on a 115M model with L8–12 distribution. It is a decorrelated implementation against which the program's solve, covariance choice and ridge can be compared — and it keys at the FFN activation of the prompt (FR1: "the entity key … at L24-26"), so its batched solve `(K*ᵀC⁻¹K* + λI)⁻¹` meets the same key-interference question the keying ablation measured today (24 last-token keys, effective rank 1.02).
- **A limitation not to inherit (Q2).** `MemitFact` carries one `target_token_id`: single-token targets only. The program's binding fragile class is multi-token coined values (C10); LARQL's editing path does not address it.
- **Lifecycle vocabulary (Q6).** L0 KNN → L1 compose → L2 MEMIT, immutable base + patch overlays + COMPILE, "edits verifiable via TRACE parity and reversible": this is the e2e map's Layer-6 lifecycle expressed as an implemented tier model, and the "hidden_dim ≥ 1024" MEMIT requirement and the compaction promote/demote steps are design points the spec can cite.
