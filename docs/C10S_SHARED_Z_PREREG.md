## 0. Where this sits, and what it is

The **§C write path**, read against the **§8.9 bar** (held-out paraphrase, full-sequence, top-1). Every knob swept so far (band, width, strength, projector, two-pass, stacked) changed how one canonical-frame target is realised. This arm changes what the target must satisfy: the value vector `z` for each coined fact is optimised jointly over the canonical prompt and two training phrasings, with the subject key unchanged and the request count unchanged (24 requests, 24 keys, one z each). It is the half of CORPUS/35 that was never run. Prior art for the shape of the objective: MEMIT-XF (`CheongWoong/mf-memit`, a shared value across task formats) and RoSE (2603.15518); their metrics are not this program's bar and only the design transfers.

**The e2e map:** write layer, compile step (§8.1 D20 solve), target definition. Nothing in the read, governance or deployment layers is touched. **What it displaces in §0.3:** per the recommended sequence it runs before the queued engine-path arms I-1 / I-2 (step 6); it is a live H-1 lead, not a §0.3 falsifier of its own.

**What this experiment can and cannot conclude (Codex item 1).** A pass advances a candidate. A miss, at any stage, means *this candidate configuration was not advanced*; it does not close the frame hypothesis, because an injection screen measures the target in the unedited model and a write-arm NULL rejects one configuration (one pair of training frames, one solve budget). No outcome here says "the frame account is closed".

## 1. Question and hypotheses

- **H-S1 (frame):** a `z` fit to three phrasings transfers to the three sealed held-out phrasings better than the canonical-only `z`, with the same write size and locality.
- **H-S0 (null — the prior):** it does not, in this configuration. CORPUS/46 F-D1 says the edit's collateral change dominates what an injected target carries; a differently fit z changes the residual and therefore ΔW, so it is a different write, not the same edit survived.
- **H-S2 (trade-off):** it transfers better but costs locality, controls, or write size.
- **The council's disagreement, made into a screen:** the memit lens says the solve already reaches 0.99 and a multi-frame `z` is still one residual through the same key; the validation lens says the stub cannot tell a frame failure from a realisation failure. Both agree on the remedy: **inject first.** The injection cell is a same-process, paired comparison (§2 cell 1): the canonical z alone has injected at 49, 54 and 51/72 across three processes (CORPUS/44:23, CORPUS/46:26, :30), so an absolute threshold is cleared by spread. Its threshold is a **screen** (does this candidate deserve a run), never a truth claim about frames.

## 2. Design (engine unmodified; the shared solve lives in the driver and enters the harness through the existing `Z_OVERRIDE` seam; one injection cell + one harness pass; a second process when the label needs it)

**The shared solve (LAW#4 — authored from `memit_dry_run/memit/memit/compute_z.py` lines 14–185, read 2026-10-06).** The engine's `compute_z` builds its rewriting prompts as `context.format(request["prompt"]) + decode(target[:-1])` over the sampled context templates (template-major; the engine's first template is the identity `"{}"`), adds the optimised `delta` to the residual at the subject's last token of every prompt (`:98–99`), records `target_init` from prompt 0 (`:95`), appends the KL prompt `"{} is a"` last (its slice at `:127–128` assumes that), averages the per-prompt negative log-likelihood (`:149–150`), **stops when the total loss — NLL + KL + weight decay — falls below 0.05** (`:164`), clamps `delta` to a ball set by `target_init.norm()` (`:175–178`), and returns `z = target_init + delta` (`:180`). The driver's `compute_z_shared(model, tok, request, hp, layer, ctx, prompts)` does the same with `prompts = [CANON, T1, T2]` in place of the single `request["prompt"]`: the rewriting set is the product of the context templates and the three phrasings, **ordering pinned template-major with CANON first inside each template** so that index 0 is still (`"{}"`, CANON) and `target_init`, the L2 ball and the weight decay are unchanged; each prompt has its own subject-last-token lookup index; the KL prompt stays last and single; **the stopping rule is the engine's, verbatim** (total loss < 0.05; nothing is tightened to reach a fit threshold). The engine file is not edited and `my_edit` gains no knob: the driver solves the 24 shared targets and feeds them through `Z_OVERRIDE` (`c10e_bandknob.py:186–189`), the seam that carried CORPUS/49–50 and is never consulted inside the LAW#5 gate. The context-template cache is process-global (`memit_main.py:305–308`), so the driver's solve and the harness's `compute_ks` see the same templates. Keys and the layer solve are unchanged.

**What the shared solve fits (Codex item 2).** The engine optimises one *displacement* `delta` added to each prompt's own activation and returns the absolute vector `z = h_CANON + delta`. High per-frame fit probabilities therefore show that `h_T1 + delta` and `h_T2 + delta` carry those frames, not that the absolute `z` does. The write aims the keyed position at the absolute `z` (through the canonical key), which is what P6-style injection measures. Both are recorded (cell 1, control c).

**Training phrasings (published here, before the run; the council's item 2).** Canonical `CANON = "The capital of {} is the city of"`. Training forms: `T1 = "The government of {} sits in"` and `T2 = "{} is a country whose capital is"`. Sealed held-out set (`PTEST`, unchanged, `c10e_bandknob.py:52–56`): `"{}'s capital city is called"`, `"If you visit {}, its capital city is"`, `"The main city and seat of government of {} is"`. Overlap rule, computed and written into the run record before the edit: after the subject slot is removed, no training form shares a word 3-gram with any held-out form (the Codex pass verified zero overlap in all nine pairs; the v1 choice `"In {}, the capital city is"` failed this rule and is withdrawn). This establishes lexical separation only, not structural independence or an author-blind hold-out: the forms are authored by the program session with the held-out set in view, which is stated here as a limit. Logged beside it: T2's subject-last-token position shares its prefix with the KL prompt `"{} is a"` under the identity template, so the KL term anchors the position T2 writes through. The forms are fixed strings in the driver, hashed into the run record.

**Inertness (LAW#5), specified (Codex item 4).** Metric: for two returned targets, the relative L2 distance ‖a − b‖ / ‖a‖ and the max-abs difference, in fp32. (i) *Floor:* in one process, run the engine's `compute_z` three times for one request on the same `ctx`; the floor is the largest pairwise relative distance; tolerance = 10 × floor, and never below 1e-4 relative. (ii) `compute_z_shared(prompts=[CANON])` must be within tolerance of an engine run. (iii) `compute_z_shared(prompts=[CANON, CANON, CANON])` must be within tolerance of an engine run — this preserves the mean objective exactly, and it is recorded that it does not guarantee identical finite-precision optimisation after a batch-size change, which is why the tolerance is measured, not assumed. (iv) *Heterogeneous-prompt check:* for `prompts=[CANON, T1, T2]` at step 0 (delta = 0), the function's per-prompt NLLs must equal, to 1e-4, a reference computed separately by three plain forward passes through the engine's own loss code path with the same lookup indices; this catches an indexing or KL-slice bug that identical prompts cannot. (v) The harness's standing LAW#5 gate (|Δexpr| ≈ 0, |Δloc| ≈ 0 with `Z_OVERRIDE` unset) must pass. Any failure → HALT.

**Cells, in order:**
1. **Injection cell (screen, ≈ 50 min):** in one process, solve the canonical z and the shared z for the 24 A7 facts on the same templates; inject each at the keyed position on the three held-out templates (the P6 procedure, `experiments/track_c/c10l_covgeom_p6_zinject.py`: overwrite the z-layer output at the subject-last token, greedy-decode the target length). Recorded: the paired outcome per (subject, template) for both targets, net wins by template and by subject; for the shared solve, per frame and per fact, the fit at stop as the engine's `exp(−nll)` per prompt (a geometric mean of teacher-forced token probabilities, not a full-sequence probability) averaged over that frame's context templates, steps to stop, `delta` norm against `max_norm`, clamp-hit flag. **Control c (Codex item 2):** with the already-solved targets, on CANON/T1/T2 compare the additive intervention (`h_prompt + delta`) with the absolute overwrite (`z`), full-sequence greedy correctness per frame; no extra optimisation.
   - **Screen rule:** proceed to the write arm only if shared − canonical ≥ 6/72 **and** the net paired wins fall on at least two held-out templates and at least four subjects (a gain concentrated on one template or one or two subjects is recorded as CONCENTRATED and does not pass the screen). The size 6 is a screening threshold whose false-positive rate is not calibrated from the three historical totals; it buys or declines a run, nothing more. Otherwise **NOT-ADVANCED-SCREEN**.
   - **Fit diagnostic:** any training frame with fit < 0.98 for any fact at stop → **UNDERFIT** (inconclusive under this solve budget); the write arm is not run, and nothing is concluded about frames.
2. **Harness pass (binding, ≈ 35 min):** A1, A2, A7 with the shared targets through `Z_OVERRIDE` for A7; the same-run canonical A7 (override unset) is the pass's own reference. Full readout: `para_full`, `canon_full`, first-token, `tf_pertok`, P(full | first), string readout, L1, same-frame fictional, `described_as`, L3, perplexity, per-layer ΔW. Added for this arm: the subject-last-token key's cosine to the canonical key under each held-out template (pre- and post-edit), so a miss can be placed on the key side; and the same-frame fictional probe run in each training frame (T1, T2) as well as the canonical frame, counted separately (the council's item 3).
3. **Second process (gate A of the sequence):** for any PARTIAL or LEAD; both counts and the per-fact agreement reported.

Runtime: ≈ 50 min + 35 min (+ 35 min). Output `results/c10s_sharedz/{inject,pass1,pass2,run}.json`; a reader beside the driver prints the label from the recorded numbers (the qualifier rules live in the reader, the prose points at it — the CORPUS/50 Q2 lesson). The driver refuses to start if any inherited harness knob is set.

- **PARTIAL** if the shared count is > 18/72 (outside the identical-baseline envelope), gain over the same-run reference ≥ 10/72 and < 30, gates hold → second process; the label stands only if the second process is also > 18 with gain ≥ 10; otherwise **PARTIAL-NOT-REPLICATED**. A gain whose shared count sits inside [5, 18] is **NULL** whatever the gain (Codex item 6: 15 vs 5 is spread, not signal).
- **TRADEOFF** if a PARTIAL- or LEAD-sized gain comes with a gate failure.
- **NULL** otherwise (this configuration not advanced).

**Locality gates (vs the same-run reference):** L1 ≤ reference + 1; same-frame fictional ≤ reference + 1 in the canonical frame **and** in each training frame; `described_as` ≥ reference − 3; L3 ≥ 29/30; generic perplexity ≤ reference + 0.5. **Write-size qualifier:** ‖ΔW_shared‖ / ‖ΔW_ref‖ (summed over layers) above 1.5 adds **-LARGE-WRITE** to any label and is recorded as evidence against H-S1's "same write size" clause (rule in the reader).

**What each buys.** LEAD (replicated) → the shared `z` becomes the default target for later arms, with I-1/I-2 behind it; it also says F-D1's reading is incomplete for this target. PARTIAL (replicated) → the frame is part of the wall; combine with the stacked re-aim as the next pre-registered arm. NULL, NOT-ADVANCED-SCREEN, UNDERFIT, CONCENTRATED or a NOT-REPLICATED label → this candidate is not advanced; the frame hypothesis stays unresolved on the register; the sequence moves to step 2 (the value-internal second key). TRADEOFF → report; step 2 next.
