## 0. Where this sits, and what it is

The **§C write path**, read against the **§8.9 bar** (`spec:388`), on the **mint harness** of CORPUS/45: engine unmodified; the value's vocabulary representation is changed before the solve. CORPUS/45 removed the span entirely (one id per value) and lifted held-out transfer from 11 to 34–46/72, leaving F-M4 open: how much of the residual gap is the *length* of the value and how much the *novelty of the pair*. This arm puts one point between the two ends: each coined word gets its own minted id, so the value is a two-id sequence whose second id is predicted from a context that already contains the first. **The e2e map:** write layer, representation of the value at the tokenizer/embedding boundary (outside the §8.1 FFN compile, `spec:307`; §4). **In §0.3:** step 3 of the agreed sequence, a diagnostic lead, not a falsifier; it runs after steps 1–2 unless the operator reorders.

**What this experiment can and cannot conclude.** A pass advances a candidate representation. A miss at any stage means *this candidate configuration was not advanced* (one init kind, three seeds, one value set, N = 24); it does not close H-19 or F-M4. The direction labels of §3 are a **routing signal for the sequence whose false-positive rate is UNVERIFIABLE from the historical totals** (Codex item 2); they identify nothing causally. CORPUS/45's qualifiers apply: not route viability, not an init-quality statement, no change to the F1 C10 status.

## 1. Question, hypotheses, and the value-set amendment

- **H-19 (span):** writing "<head> <modifier>" as two minted ids (init N) lands between the one-token mint and the multi-token string on the binding count, with the loss at the second id. Stub: `hypotheses.md:194–196`.
- **H-19-null (pair novelty — the prior):** the two-id value lands with the string: the second id must be predicted from a (head, subject) context the model has never seen, and the solve supervises it only through the single key displacement (§2); CORPUS/46 F-D4 says a difference under 12/72 is within what the init alone produces.
- **H-19-tradeoff:** the ordering holds but a locality, perplexity, write-size, false-fire or bigram gate fails.

**The frozen A7 values cannot be split-minted (departure 1, confirmed by both reviews).** `build_stimuli` assigns heads by `coined_head[(i*2+1) % 24]` and modifiers by `coined_mod[(i*3+2) % 24]` (`c10e_bandknob.py:246–249`): 12 distinct heads each on two subjects, 8 distinct modifiers each on three; 8 heads (Drennik, Vythorn, Vorlex, Kessivar, Halquin, Marsduq, Glimsto, Fluvane) are `FICTION` subjects (`:57–61`), three (Lurmax, Brindu, Yastov) are subject prefixes; `register` uses `single_word=False` (`c10l_mint_lib.py:26`). Codex's tokenizer-only check (`results/c10u_mint2_review_tokenizer_check_20261006-133250.json`, no model load): under the existing registration **33/96** CANON+PTEST prompts change tokenisation; with `single_word=True` **0/96** change but **0/24** target pairs encode as the two minted ids (and the 8 exact collisions remain — advisor item 2). Step 0's P2a (`c10l_mint_step0.py:63`, halt `:70`) would fail by construction.

**Resolution adopted — A7-V2, a scientific-scope amendment that needs the OPERATOR's acceptance before freeze (advisor item 2, Codex item 1).** V2 = 24 values from 24 new heads × the 24 `coined_mod` words (`:234–238`, injective). Head rules, published and SHA-256-hashed (`lib:174–175`) into step 0 with the overlap table: coined; no equality, prefix or substring relation with any `FICTION` subject, any L1/L3 country (`:277–278`), any `FRAME_SUBJECTS` word or any word of the extended P2 prompt inventory (§2); each head ≥ 2 BPE pieces so the string baseline stays multi-token. **What V2 changes, stated plainly:** (i) the head identities; (ii) the shared structure of the frozen set (12 heads × 2, 8 modifiers × 3) — in V2 every head uniquely identifies its modifier, which permits a head→modifier shortcut without continued subject dependence (Codex I-INFER), so the pairing problem itself is different and the §3 bigram control is mandatory; (iii) comparability — these stimuli are the instrument behind every CORPUS/39–50 A7 number, and matching envelopes cannot restore it. All arms run on V2 in the same comparison block; CORPUS/45 is context, not the comparator. The redraw carries its own Decision-ID line, `D-C10u-A7V2`, in runbook §5. **Named fallback if the operator declines V2:** modifier-only minting on the frozen values — P2a-clean because A7 value strings are excluded from `all_harness_prompts` by design (`lib:180`) and the modifiers are not subjects; target lengths 3–4 ids (Codex check); keeps CORPUS/45 comparability, forfeits the uniform two-id value, so it tests partial compression, not "one token per word". A non-word-boundary split of the frozen strings is not adopted (abandons "one per word", needs its own P2 audit).

## 2. Design (engine unmodified; driver on the `c10l_mint_lib.py` primitives through the harness seams `ARM_HOOKS` and `Z_OVERRIDE`; one step 0 per (arm kind, seed); comparison blocks replicated in fresh processes)

**Registration and initialisation (`c10l_mint_lib.py`).** `register(tok, values)` adds one `AddedToken(" " + v, normalized=False, lstrip=False, rstrip=False, single_word=False)` per string (`:24–27`), fails closed on fewer tokens added than strings (`:27–29` — V2 must have 48 distinct words), asserts contiguous ids from `SPARE_START = 151665` (`:10`, `:30–32`; 271 spare rows to `VOCAB_ROWS = 151936`, `:11`) and `tok(" " + v) == [id]` (`:33–36`). Mint-2 registers the 48 words (24 heads then 24 modifiers; ids 151665–151712); mint-1 the 24 whole strings (`minted_strings`, `:20–21`; ids 151665–151688). `assert_tied` (`:44–48`): each row is also the output row. **Initialisation fact (corrected, Codex item 3):** `build_init(..., "N", seed)` draws rows sequentially from one `torch.Generator().manual_seed(seed)` (`:72`, `:84–86`), so **the first 24 of the 48-row N(seed s) equal the 24-row N(seed s)** — mint-1's 24 value rows and mint-2's 24 head rows are the same vectors; this pairing is kept and hashed (`sha256_tensor`, `:162–163`; rows checked by the driver, `c10l_mint_arms.py:99–101`). `set_rows` (`:95–97`) is the only embedding write; `get_rows` (`:100–101`).

**What one request with a two-id target does in the solve (`memit_dry_run/memit/memit/compute_z.py`).** One request per fact, `{"prompt": CANON, "subject": c, "target_new": {"str": " " + value}}` (`bandknob:96–97`, `:480`); `my_edit` solves one `z` per request (`:191`). `compute_z` tokenises the whole target (`:41–43`: `[ĥ_head, ĥ_mod]` for mint-2), builds rewriting prompts as `context.format(prompt) + decode(target_ids[:-1])` (`:46–50`, the head appended as text), places both ids at the last two target positions (`:60–65`), adds one `delta` at the key (`:98–99`) — **the subject's last token** (`find_fact_lookup_idx`, `:68–73`), with the frame tokens " is the city of" (`bandknob:51`) between the key and the value slot (seam fix, Codex item 7) — averages the per-position NLL over the target length (`:149`) and over prompts (`:150`), adds the KL term on `"{} is a"` (`:50`, `:127–128`, `:151–153`) and weight decay (`:154–156`), stops below 0.05 (`:164`) — **the stopping rule is not touched** (Codex item 4) — clamps (`:175–178`) and returns `z = target_init + delta` (`:180`). The printed "avg prob" is `exp(−nll_each).mean()` (`:162`): the **mean over prompts of each prompt's geometric mean over positions** (advisor item 5) — one number per value, not per position.

**Capture of the solved targets (seam fix, Codex item 7).** `ARM_HOOKS` run after `my_edit` (`bandknob:494–495`) and `_ARM_STATE` is read-only solve state without `zs` (`:409–412`); `zs` is local to `my_edit` (`:191`). Mechanism adopted for the implementation review: the driver solves the 24 targets itself with the engine's own `compute_z` on the process-global context templates (`memit_main.py:304–308`) and supplies them through `Z_OVERRIDE` keyed by (subject, target string) (`bandknob:185–189`, `:405–408`), so the write's target and the captured `z` are one object; `Z_OVERRIDE_HITS` must equal the number of A7 arms in the process; the override is never consulted in the LAW#5 check (`:406`), which must pass in every process. **Frozen context set per comparison block (Codex item 2):** the first process of a block writes `CONTEXT_TEMPLATES_CACHE` to a file; every later process of the block sets that module global from the file before any solve — a driver assignment, no engine edit; the templates' hash enters every run record.
