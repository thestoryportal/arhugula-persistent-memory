## Verdict for this program

**Not an experiment runner for us; a bounded literature instrument for the research pass.** What OpenResearch orchestrates (one coding agent per research direction in a private git worktree, a frozen experiment tree, run logs as evidence, a "promote the winner" loop) is a looser version of what the program already runs under DISCIPLINE: pre-registration, controls and shams, LAW gates, mechanical readers, the close-out hook and cross-family review have no counterpart in it. Its auto-research loop is an optimizer of the autoresearch kind, so it would be **fenced** (DISCIPLINE §3) exactly like T-autoresearch-twopass. The one capability the program lacks and it supplies is `orx discover` / `orx paper`: alphaXiv full-text keyword retrieval, alphaXiv semantic retrieval, and the OpenAlex scholarly graph from the terminal, no login. That fits the research pass's "other science-grounded agentic tools" slot beside InfraNodus, as a lead generator whose hits go to the pass log, never to CORPUS. Logged as **T-openresearch** (lead; fenced; instrument only).

## What it is (verified)

- `openresearch-cli` **v0.2.16**, Rust (a port of a TypeScript CLI), MIT, binary `orx`; GitHub shows 6.6k stars (web fetch, not the clone). The desktop app (macOS 11+, Windows beta, Linux AppImage) wraps the same CLI; `orx up` serves a local dashboard at `127.0.0.1:4791`. `AGENTS.md`: the CLI owns "the local CLI, dashboard and API, SQLite store, coding-agent integrations, experiment orchestration, and execution backends"; the companion service `openresearch.sh` owns accounts, organizations, sandbox provisioning and managed-compute catalogs. "Research projects, experiments, runs, logs, and artifacts remain local to `orx`."
- **Agent model.** `SYSTEM_PROMPT.md` is injected verbatim into every agent session — Claude Code via `--append-system-prompt-file`, Codex via `developerInstructions`, OpenCode via its config — and the `agent-skills/` modules are installed as native skills into the session's worktree. Each chat session gets **its own git worktree** of the project repository. Supported harnesses: Claude Code, Codex, OpenCode, Cursor, Antigravity; local models through OpenCode + LM Studio / oMLX / Ollama / any OpenAI-compatible loopback server (`docs/local-models.md`).
- **Experiment tree** (`orx-experiment-tree`): a project is a tree of nodes; the root holds code + one fixed run command; children branch on `orx/<slug>` git branches and inherit the command. Four cardinal rules: never edit a node once a run has answered it (frozen, permanently); the run command and environment are a fixed contract, identical on every node; **vary code, not knobs-in-the-command (no env-var sweeps)**; grow the tree downward ("stacked bushes": a small fan per decision, then descend onto the winner). Loop: `orx exp wait` returns on the first completion; per completion the agent repairs / refills / promotes / stops; repair cap two runs; stop after ~3 failed or regressed runs; write-up as an artifact.
- **Evidence** (`orx-evidence`): run logs are the evidence channel; the run command must print final metrics, a summary block and the effective config; "never infer a result from run status or memory"; claims in chat carry `<file>` / `<run>` tags.
- **Literature** (`orx-lit-review`): `orx discover keyword|embedding|openalex|biorxiv|pubmed "<query>" [--published-after/-before] [--prioritize default|recency|historical|popular] [--limit]`; `orx paper <id|url> [--full]` returns an alphaXiv report with full-text fallback (or OpenAlex/bioRxiv/PubMed metadata). "No login is required." Retrieval is budgeted by a self-estimated difficulty (0–2 follow-up rounds), deduplicated by id/DOI/arXiv id/title, ranked 5–15; citations point at `alphaxiv.org/pdf/<id>?page=N`. **UNVERIFIED:** whether `discover` calls alphaXiv's public API directly or proxies through `api.openresearch.sh` (the `client.rs` head covers orgs / compute catalog / sandboxes only).
- **Compute.** Local runs need no account. Managed compute, instance provisioning and orgs need `orx login` (loopback OAuth, token at `~/.config/openresearch/credentials.json`); the catalog is GPU offers plus a RunPod-only CPU catalog. Backends: SSH, Slurm, Kubernetes, Modal, Tinker, Ray, Hugging Face Jobs. **All out of scope here (D-HW-1, local-only, no rentals).**
- **Telemetry** (`src/telemetry.rs`): opt-out usage events to `https://api.openresearch.sh/analytics/v1/cli-events` under a random per-install UUID, **official builds only** ("Source builds never send production telemetry or generate an install id"); `orx telemetry off` or `--no-telemetry`; the opt-out itself is queued once. Events exclude code, prompts, paths, repo names, project/experiment ids; the onboarding profile's category and free-text fields are sent.

## Risks and constraints for a trial

- `install.sh` installs an **unsigned** binary (README: managed Macs may block it; the notarized desktop app is the alternative). Building from source needs `cargo` + a working linker — **not available on this Mac** (CLT broken, `mbp-command-line-tools-broken`), so the trial uses the official binary with `orx telemetry off` first, or the desktop app's Settings → "Install the `orx` command".
- Network: `discover` and `paper` hit public endpoints; the run itself sends nothing about the program unless the analytics are left on. Nothing of ours is uploaded by a `discover` query beyond the query string.
- Scope: **no project, no experiment tree, no `orx up`** in the trial — the program's harness is the runner. The install must not touch `.claude/` skills (`orx install-skills` writes into coding-agent skill dirs; do not run it).
