## 0. Where this sits, and what it is

The **§C write path** read against the **§8.9 bar** (held-out paraphrase, full-sequence, top-1). Every arm so far has keyed each fact once, at the subject's last token, and asked one target `z` to carry the whole 4–6-token value from that one position. This arm keeps that request unchanged and adds, per fact, **one more request keyed at a token inside the value**, whose target is the remainder of the value: 48 requests, 48 keys, two `z` per fact, targets as the engine computes them per key (no `Z_OVERRIDE`). The position is not chosen by hand: it is the token before the maximum-surprisal boundary of the value under the base model (H-10) or the maximum covariance-leverage position under the band covariance (H-5), computed in step 0 and published before the run.

**The e2e map:** write layer, compile step (§8.1 D20 solve), the **key (address) definition** — the first arm of the program to change the address side for a coined value rather than the target or the solve geometry. The sequence's criterion 3 ranks realisation arms above address arms; this one is here because the later value tokens currently have no objective at any key position but the subject's (step 2 row, `recommended_sequence.md:21`). Nothing in the read, governance or deployment layers is touched. **What it displaces in §0.3:** per the sequence it runs after step 1 and before the engine-path arms I-1 / I-2 (step 6); it is a live H-10/H-5 lead, not a §0.3 falsifier of its own.

**The CORPUS/44 residual record, read with the corrected sign.** The step-0 script defines `rho_c_band = ‖z − cur_after‖ / ‖z − cur_before‖` (`experiments/track_c/c10l_covgeom_step0.py:134`): the fraction of the residual norm that **remains** after the write at the canonical keyed position. The record gives R0 `rho_c_band 0.0282`, `rho_p_band 0.2315` (`results/c10l_covgeom/step0_offline.json`, `regularisers.R0.band`; per held-out template 0.314 / 0.209 / 0.119). So the edit installs the target at the canonical keyed position to ≈ 97 % in norm, and ≈ 77 % on the paraphrase prompts, while `para_full` sat at 13/72 — **in that reconstruction, a large canonical-position realisation shortfall is weakened as the account of the held-out miss (unmeasured in the behavioural run; F-A4 cross-process ΔW variation ≤ 4.35 %)**; norm installed at the keyed position does not translate into held-out behaviour. The v1 wording "≈ 3 % realised" (and CORPUS/44's "realises ≈ 3 % of z") is reversed; the CORPUS/44 wording correction is pending through the program's CORPUS gate and is not made here. Codex's drift note stands with it: 0.028 was measured on the subject-key configuration and is a prior for it, not an assumed realisation rate for the second keys.

**What this experiment can and cannot conclude.** A pass advances a candidate. A miss, at any stage, means *this candidate configuration was not advanced* — one position rule per fact, one extra key, engine targets, this solve budget — and nothing more; the stub's "a second closed-form key alone cannot carry the continuation" is **not** adopted as a NULL reading (`prereg_stubs.md:34`). A LEAD is a write-path mechanism lead under one relation label, not §8.9 contract closure. Two readings of a gain are separated by design: **direct address** (H-T1; needs the duplicated-canonical control, §2) and **configuration improvement** (the count rose under 48 requests, cause unattributed).

## 1. Question and hypotheses

- **H-T1 (direct address):** a second key at the chosen value-internal position, with its own target fit to the remaining value tokens, raises A7 `para_full` over the same-run single-key arm with locality held, and over the 48-request duplicated-canonical control, because the continuation tokens receive a write at an address the held-out prompts reach once the first value token is produced.
- **H-T0 (null — the prior):** it does not, in this configuration. The subject-key write already installs its target in norm at the keyed position (ρ_c 0.028 remaining) and ≈ 77 % on paraphrase prompts, and that does not translate into held-out behaviour; a second keyed position adds an address but does not change that translation, and the held-out prompts never contain the frame the second key was taken in.
- **H-T2 (bleed / subject-free):** the count rises, but the second key is nearly subject-independent at layers 4–8 (token identity dominates the `down_proj` input, the advisor's inference) and the write is an n-gram completion "prefix → remainder" that fires from the prefix alone; §8.9 is matched but H-T1 is not. Read from the subject-free prefix probe and the per-prefix bleed gates.
- **H-T3 (request count):** the gain comes from 48 requests as such — at zero cache, duplicating the 24 canonical requests doubles both data terms of the solve (`c10e_bandknob.py:209–210`), equivalent to halving the ridge `L2 = 1.0` (`:29`) — not from the address. Read from the duplicated-canonical control.
- **H-T4 (key side):** the second key does not transfer across phrasings (its cross-template cosine is at or below the subject key's own, computed in step 0 before any write), so the address is never reached from a held-out prompt. A pre-registered reading, not a stop.

## 2. Design (engine unmodified; the second request list enters through a driver wrapper around `my_edit`; step 0 offline; one harness pass; a second process when the label needs it)

**How a key inside the value is addressed (LAW#4 — authored from the sources read 2026-10-06).**
- `compute_ks` builds `context.format(request["prompt"])` with `words=request["subject"]` per request and context template (`memit_dry_run/memit/memit/compute_ks.py:19–37`), takes the input side of `rewrite_module_tmp` (`:35`, `[0]` at `:37`) and averages over the templates per request (`:44–49`). The hparams fix `fact_token: "subject_last"` (`configs/hparams/qwen25_3b_memit_hparams.json:5`) → `subtoken="last"` (`compute_z.py:208–216`).
- `get_words_idxs_in_templates` (`memit_dry_run/memit/rome/repr_tools.py:43–99`): one `{}` per template (`:52–54`); the prefix's trailing space is stripped (`:66–67`) and the word becomes `" " + word.strip()` (`:70`); prefix, word and suffix are tokenised **separately** (`:75`); the index is `prefixes_len + words_len − 1` (`:85–90`). The keyed token is whatever token ends the `subject` string; templates change only `prefixes_len`.
- Precedent: the CORPUS/43 last-token cells pass `prompt="The capital of {}"`, `subject=f"{c} is the city of"` so `subject_last` keys the final `" of"` (`experiments/track_c/c10e_bandknob.py:477–478`; validity print `:481–485`).

**The second request:** `prompt = "The capital of {}"`, `subject = f"{c} is the city of" + tok.decode(V_ids[:j])`, `target_new.str = tok.decode(V_ids[j:])`, with `V_ids = tok(" " + V)["input_ids"]` (the canonical target's tokenisation: `c10e_bandknob.py:96–97` prepends the space, `compute_z.py:41–43` tokenises standalone) and `j ∈ {1, …, n−1}` the published key position (value token `j`, 1-based; `n` excluded, empty remainder). Built by hand, not through `req()` (`:97` would prepend a second space). In the engine: rewriting prompts `context.format(prompt) + decode(target_ids[:-1])` (`compute_z.py:46–50`) formatted with the extended subject (`:53–57`) — the same string as the canonical request's rewriting prompt — with the remainder's ids sliced off the end (`:60–65`); lookup index at the extended subject's last token (`:67–73`, `:234–256`); `delta` added there (`:98–99`), `target_init` from that position (`:95`); loss = mean NLL over the remainder (`:149–150`) + KL on `"{} is a"` formatted with the extended subject (`:50`, `:54`, `:127–128`) + weight decay (`:154–156`); stop at total loss < 0.05 (`:164`) or 25 steps (hparams `:6`); clamp `0.75 × ‖target_init‖` (`:175–178`, hparams `:3`). In `my_edit`, two columns of `K` (`c10e_bandknob.py:196`) and of `zs − cur` (`:191`, `:197–202`) per fact, solved jointly (`:209–211`), cache `:218–220`. Canonical request unchanged (`:480`); `Z_OVERRIDE` `None` (`:407`), hits 0. Order pinned blocked: 24 canonical in `FICTION` order, then the 24 second requests.
- **The KL anchor is an objective change and is recorded as such (Codex table):** for the second request the KL prompt is `"<c> is the city of <prefix> is a"`, evaluated at the lookup token, i.e. the value-prefix position (`compute_z.py:127–128`), so it regularises next-token predictions **at the position whose next token the remainder must change**, and may oppose the fit. The engine is kept unchanged; `kl_loss` and `nll` at stop are recorded per request; the CORPUS/43 last-token cells ran under the analogous anchor (`c10e_bandknob.py:478` comment).

**Admission — tokenizer-only alignment audit (step 0, before any optimisation; repeated in every process against that process's sampled context templates, `get_context_templates`, `memit_main.py:304–316`, called at `c10e_bandknob.py:182`, without reselecting the frozen positions; any run-time failure → HALT, never fall through to another `j`).** For every second request and every context template `t`, with `b` = number of tokens of `tok(t.format(prompt).format(subject))` and `m = len(V_ids[j:])`:
- the prefix ids of the truncated rewriting input `tok(t.format(prompt).format(subject) + decode(V_ids[j:][:-1]))` equal those `b` ids exactly; the input has length `b + m − 1`; the index `get_words_idxs_in_templates` returns is `b − 1`; the engine's end-slice (`:65`) therefore places the labels at `b − 1 … b + m − 2`, and the ids at `b − 1 … b + m − 2` of the full sentence `tok(t.format(CANON.format(c)) + " " + V)` equal `V_ids[j−1 : n−1]`, i.e. the keyed token is `V_ids[j−1]` and the labels are the remainder; `tok(target_new.str) == V_ids[j:]`;
- the KL prompt `"{} is a".format(subject)` is checked separately: its returned index decodes to `V_ids[j−1]`;
- the decoded token at the returned index equals the intended token for all 48 requests (the `:483–485` print extended to all 48 and to one sampled template, not only the identity template).
At step 0 a `j` failing any check is inadmissible for that fact; the admissible set `|adm_c|` is published per fact.

**Step 0 (no write, minutes; `experiments/track_c/c10t_secondkey_step0.py`, to be written).** For each A7 value (`build_stimuli`, `c10e_bandknob.py:246–249`; `FICTION[0:24]`, `:57–64`) under the base model:
- (a) *Surprisal (H-10):* `s_j = −log p(V_j | CANON.format(c) + decode(V_ids[:j−1]))`, `j = 1..n`, teacher-forced. **Unconstrained pick** `j* = argmax_j s_j` over all `j` (reported; `j* = 1` means the frame token `" of"`). **Internal pick** `p10 = argmax_{j ∈ 1..n−1} s_{j+1}` (the token before the highest internal boundary); ties → smallest `j`. No fact is ever keyed at a frame token.
- (b) *Leverage (H-5) — an explicitly experimental protected-subspace heuristic.* For every token position `p` of the canonical sentence (subject, frame, value) and band layer `ℓ ∈ {4..8}` (hparams `:2`): `k_p^ℓ` = the `down_proj` input at `p`; `Σ_ℓ = get_cov(model, tok, hp.rewrite_module_tmp.format(ℓ), hp.mom2_dataset, hp.mom2_n_samples, hp.mom2_dtype)` as `compute_P` reads it (`c10e_bandknob.py:169–172`; raw second moment, `memit_main.py:240–280`). `compute_P` sends the directions with `S < NULL_THRESH` (0.005) to the projector (`:28`, `:173–175`), so the score `kᵀΣ⁺k` over the directions with `S ≥ 0.005` is leverage **in the protected subspace the write cannot use** — the v1 claim that it was "the subspace the solve keeps" was reversed. It is retained as the H-5 selector only as a heuristic; the tiny singular values are not inverted. Reported beside it, per position and layer: `‖P_ℓ k‖² / ‖k‖²` (the share of the key the write can use), the per-layer winner and its margin over the runner-up, the stability of the pick to the cut (0.005 vs 0.05), and the winner under the per-layer-max-normalised five-layer mean. Positions are classified consistently: subject tokens, frame tokens, value tokens `1..n−1` (writable), value token `n` (not writable). **Unconstrained pick** = argmax over the sentence; **internal pick** `p5` = argmax over `1..n−1`; ties → smallest `j`.
- (c) *Spending screen and merge (the stub's rules, `prereg_stubs.md:30`, made executable):* a rule is **dropped** when its unconstrained pick lands on a non-writable position (subject token, frame token — `j* = 1` counts here — or value token `n`) on more than 12/24 facts; this is a budget choice, not evidence against internal keys. A surviving rule keys **every** fact at its internal pick, moved to the nearest admissible internal position (ties → smaller `j`) if the pick is inadmissible; an empty `adm_c` for any fact → **INVALID-ADMISSION**, the arm is not run (the population is never changed). Agreement is counted on the **pre-admission internal picks** (`p10 = p5`); ≥ 20/24 → the arms **merge** into one arm B that takes `p10` on the disagreements; otherwise B10 and B5 run separately. Published: `j*`, `p10`, `p5`, `|adm_c|`, agreement before and after admission, the final `j` per fact.
- (d) *Overturning test before any write:* the second key's cross-template cosine — `k_second` under CANON against `k_second` under each `PTEST` template (`c10e_bandknob.py:52–56`) with the same prefix appended, per fact and layer — beside the subject key's own. **Pre-registered reading:** if the median across facts and layers is at or below the subject key's median, H-T4 is recorded as the standing reading before the run; the run still happens (the sequence's choice), and a LEAD is then read with H-T2/H-T4 in view.
- (e) Published and hashed into the run record: everything in (a)–(d), the 48 request dicts, and a normalised-overlap audit of the second-request subject strings against `PTEST`. Limit stated: the positions are functions of the base model, the sentence and the covariance only, but the author has the held-out templates in view.

**The harness pass (binding, one process).** Arms, each after `restore_layers` (`c10e_bandknob.py:473`) with the same `P` (`:462`) and base snapshot: A1, A2, **A7-single** (reference, list identical to `:480`), **A7-dup** (the 24 canonical requests duplicated → 48 requests; the request-count / ridge control), **A7-second** (B, or B10 and B5). The lists enter through a **driver wrapper** around `H.my_edit`, restricted to the candidate arms by matching the request targets against the A7 `Vmap` (`my_edit` receives no arm name and `_ARM_STATE` lacks it, `:487`); the wrapper counts its substitutions (one per candidate arm; the reader checks the count) and asserts that the 48-request list reached `my_edit` and the hooks; it is never active in the LAW#5 gate (`:433`). Full readout as the harness records it (`:365–398`, `:313–337`, `:475`/`:492`, `:213–215`); LAW#5 gate as it stands (`:415–446`: |Δexpr| < 0.05, |Δloc| < 3). Hooks (`ARM_HOOKS`, `:404`, `:494–495`), each run on base (pre-edit), A7-single, A7-dup and the candidate arms:
- (a) **F0** — `frame_probe()` on the six never-edited `FRAME_SUBJECTS` in the CANON frame (`c10p_twopass_arms.py:30–42`; flip = top-1 is the first token of any edited A7 value).
- (b) **F1 — 24 per-prefix bleed gates:** for each fact `i`, the six prompts `"The capital of {s} is the city of" + decode(V_ids^i[:j_i])` over the six never-edited subjects; recorded per prefix: next-token hits (top-1 = `V_ids^i[j_i]`) and full-remainder hits (greedy, `full_seq_match`), on base, A7-single and the candidate; newly induced hits = post-hits that were not base hits.
- (c) **Subject-free prefix probe (24 prompts):** the pre-registered neutral frame `"The name is" + decode(V_ids^i[:j_i])` — no subject, no capital frame; next-token and full-remainder hits, same arms.
- (d) **Keygram** of the 48 keys per band layer (`stats()`, `c10k_keying_ablation_keygram.py:13–17`, on the `K` of `:196`): subject block, second block, joint; **and the geometry the solve uses**: the same statistics on `P_ℓ K`, the cross-block cosine (each fact's second key against its own and the other subjects' keys), and the realised residual after the write at both keyed positions and on the held-out prompts, computed as `c10l_covgeom_step0.py:103–108, :132–134` do (remaining fraction, sign as corrected in §0). Comparators are CORPUS/43's values (≥ 0.985 / 1.02; 0.02–0.07 / 16–23), not thresholds.
- (e) **Prefix reached:** per fact and held-out template, whether free greedy generation produces `V_ids[:j]` (the address must be reached naturally for H-T1; a gold-prefix cosine cannot show that); the per-fact 24-vector and the /72 count.
- (f) **Bystander relation diagnostics:** `"{c} is a"` and `"{c} is associated with"` on the 24 edited subjects, top-1 pre vs post, flips to any edited value's first token counted (no harness seam exists; the only non-written-relation probe is `"{c} is described as"`, `:475`). Caveat recorded: the KL term is evaluated at the subject lookup token (`compute_z.py:127–128`), not at the final token of `"is a"`, so the continuation measured here is not directly KL-protected.
- (g) Per-request fit at stop for all 48 (`exp(−nll)`, `kl_loss`, steps, clamp-hit), the CORPUS/36 z-probe convention.

**Second process (gate A):** for any PARTIAL or LEAD, a fresh process with the identical positions file (admission re-run there); both counts and the per-fact agreement reported; every validity and locality gate must hold in **both** processes.
