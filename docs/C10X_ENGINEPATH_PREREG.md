## 0. Where this sits, and what it is

**The e2e map (`docs/SPEC_E2E_GROUND_TRUTH.md` §C, `:22–31`; read against §F, `:64–65`).** Both arms sit inside the compile step of the write path — the per-commit solve that turns a `.larql` patch into the `.vindex` overlay mounted in Phase 2 of the commit (`:30`), placed as `docs/C10V_LAYERPICK_PREREG.md:7` places the §8.1 solve. Key side, layer set (4–8), covariance/projector, ridge and the read path are untouched. The bar is §F's L2 behavioural probe in its §8.9 form: held-out paraphrase, full sequence, greedy, top-1. Nothing in the read, governance or deployment layers is touched. **§0.3:** step 6 of the agreed sequence (integrated queue row 4).

**Write-only ruling, checked (`EXPERIMENT_RUNBOOK.md:330` (2); `recommended_sequence.md:11`).** Both arms stay a per-commit write derivable from the patch with no training set and no weight-training loop. I-2 = the engine's own `compute_z` (one 25-step optimisation of one hidden-state vector per fact, `memit_dry_run/memit/memit/compute_z.py:104–172`, `configs/hparams/qwen25_3b_memit_hparams.json:6`) called at layer 4 instead of 8, one deterministic forward pass, and the harness's closed-form ridge solve per layer. I-1 = the same 25-step single-vector optimisation with a different per-token loss, then the unchanged solve. The only iterative step in either arm is the one the engine already performs.

**Two premises in the brief, corrected before design.**
1. *"The write realises only about 3 % of its target at the keyed position."* Reversed. ρ_c is a **remaining**-residual ratio, `‖z − cur_after‖ / ‖z − cur_before‖` (`experiments/track_c/c10l_covgeom_step0.py:134`, `rel` at `:74–75`); ≈ 2.8 % of the canonical residual norm *remains* after the band write in step 0's offline reconstruction, ≈ 23 % on paraphrase prompts (`CORPUS/44_C10L_COVGEOM_SPARSEBAND.md:43`, the append-only correction; `recommended_sequence.md:13` and `prereg_stubs.md:75` still carry the old wording). Consequence for I-2: FE's published mechanism is that backward spreading leaves a large final residual (Table 2, "Dividing": 0.96 → 0.36 remaining over layers 4–8 on Llama3-8B-Instruct; FE leaves 0.03, Table 5). This harness already leaves ≈ 0.03 at the canonical keyed position, so the canonical-position residual cannot be what FE fixes here; what FE can still change is **which layers carry the write** (FE front-loads: 0.37 remaining after layer 4 alone, Table 5) and therefore the collateral change at non-keyed positions and on paraphrase prompts — the F-A3 / F-D1 confound (`CORPUS/44:31`, `CORPUS/46:30`).
2. *"Value tokens two onward have no objective."* Not true of the target solve: `compute_z` scores **every** target token (`compute_z.py:60–65` places all target ids; `:141–150` averages their NLL), and z reaches 0.99 on the full multi-token target (`CORPUS/36:28`). What has no objective is the **weight solve at the value positions**: keys are read at the subject's last token only (`find_fact_lookup_idx`, `compute_z.py:68–73`; `compute_ks.py:19–50`; harness `c10e_bandknob.py:196`). The post-write per-position weakness is real — A7-multi teacher-forced held-out hits by position 59, 66, 51, 19, 34, 20 /72, the drop at the fourth token (`CORPUS/45:24`). Consequence for I-1: OverTone reweights the tokens *of the target objective* (Eq. 2–3); it adds no objective at the value positions of the weight solve. I-1 here tests the narrower claim "a token-reweighted target is a better target for the same write", not "the continuation gets an objective". (The value-position key was step 2, CORPUS/53: NULL-LARGE-WRITE.)

**What this experiment can and cannot conclude.** A pass advances a candidate engine-path change. A miss means *this candidate configuration was not advanced* — one hyperparameter setting per arm, one band, one seed, N = 24. The stub's "Bad: the closed-form spreading itself is the limit" (`recommended_sequence.md:26`) is not adopted as a NULL reading; a NULL joins CORPUS/37–39, 44 and 50–53 as one more write-path configuration not advanced on this harness.

## 1. Question and hypotheses

- **H-X2 (I-2, forward replay):** building the band's per-layer targets by solving z at the first band layer (4) and forward-propagating it (FE §5, App. A.3), each layer edited toward its own replayed target with the undivided residual, raises A7 held-out `para_full` over the harness's backward spreading (arm A, same process) at the same locality.
- **H-X2-null (the prior):** it does not. The canonical residual is already ≈ 97 % installed (§0 item 1); FE's evidence is on CounterFact/ZsRE real-entity edits with a MEMIT λC regulariser (§6.1), not on a null-space-projected ridge-1 solve with coined values; CORPUS/37–39 and 44 F-A2 moved the layer allocation six ways without a LEAD.
- **H-X1 (I-1, OverTone objective):** solving each target with OverTone's clipped forward KL to a filtered, dynamically mixed target distribution per value token (Eq. 2–3, Algorithm 1) raises A7 held-out `para_full` over the engine-objective target (arm A, same process) at the same locality.
- **H-X1-null (the prior):** it does not. The engine target is already fit (0.99, `CORPUS/36:28`) and already carries 49–51/72 by injection (`CORPUS/44:23`, `CORPUS/46:30`); the edit, not the target, loses the value (F-D1). OverTone was applied by its authors to FT-M, LoRA, MELO and WISE; ROME and MEMIT appear only as reference rows with EasyEdit defaults (§4.1; App. B.1) — the transfer to a MEMIT z-solve is this program's own and unvalidated. Against the null: CORPUS/51 F-S2 shows a changed target can move injection by +18 (51 → 69/72), so the target side is not inert.
- **H-X-tradeoff:** an arm gains but costs locality, the controls, or write size (FE's undivided first-layer residual can enlarge ΔW at layer 4; OverTone's early clip can underfit the canonical frame).

### 2.2 Arm I-2 — forward-replay target construction (FE)

**What FE does (paper).** MEMIT optimises the hidden state at the *final* decisive layer and spreads the residual backward, `m_l = h_l + (m_L − h_L)/(L − l + 1)` (App. A.2, Eq. 15–19). FE optimises the hidden state at the *first* decisive layer by the same gradient procedure (§5; App. A.3, Eq. 20–21), then sets each later layer's target to the hidden state at the decisive position obtained by a plain forward pass with `m_1` substituted (Eq. 22–24); "with the exception of the second stage, all other components remain identical to the standard LTE method MEMIT" (§5). Per-layer edit: `Δ_l = argmin ‖Δ_l k_l − (m_l − h_l)‖²` (Eq. 14), sequential shallow to deep. Residual metric: `‖m_L − h_L^{(after l)}‖ / ‖m_L − h_L^{(0)}‖` (App. A.5).

**This harness's transcription (the driver; no engine or harness line changes).**
1. *Targets, solved on the pristine model before any write* (the engine's convention, `memit_main.py:104–149` before `:152`), for every arm (A1, A2, A7) and subject `c`: `rq = H.req(CANON, c, value)`; `z4 = compute_z(H.model, H.tok, rq, hp, 4, ctx)` — the engine function, unmodified, `layer = 4` (`compute_z.py:14–21`; the loss layer stays 35, `:76`; the clamp radius becomes `0.75 · ‖target_init_4‖`, `:175`); `ctx = get_context_templates(model, tok)` (the process-global list, `memit_main.py:304–323`).
2. *Forward replay* (one no-grad forward pass of `CANON.format(c)` without the value, batch 1): a forward hook on `model.model.layers[4]` sets the block output at `idx = find_fact_lookup_idx(CANON, c, tok, "subject_last")` (`compute_z.py:234–267`) to `z4` (P6 overwrite semantics, `c10l_covgeom_p6_zinject.py:38–41`, cast to the hidden dtype); hooks on blocks 5–8 capture their outputs at `idx`. `m_c = [z4, m5, m6, m7, m8]`, stored fp32 and SHA-256-hashed per arm. Set semantics (not the solve's additive `delta`) is used because the canonical prompt under the identity template is prompt 0 of the solve (`memit_main.py:308`), where `target_init + delta = z` by construction (`compute_z.py:95`, `:180`). Only the canonical prompt is replayed because the harness reads `cur` on the canonical prompt only (`c10e_bandknob.py:197–201`); the spread of the replayed `m_8` across the six context-templated prompts is recorded as a diagnostic.
3. *The write* (`fe_edit(hp, requests, P, cache_c)`, a driver function authored line for line from `my_edit:181–221`, with exactly three changes): (a) the per-layer target `M[i]` = the stacked `m_c[i]` from a strict table `FE_TARGETS[(subject, target str)]` — a missing key raises (HALT), unlike `Z_OVERRIDE`'s silent fallback (`:186`); (b) `cur` is read at **`layer`** instead of `z_layer` (`:197–201` with `z_layer → layer`; the same engine function `get_module_input_output_at_words`, the same canonical prompts, `module_template = hp.layer_module_tmp`); (c) `resid = tgt` — **no division** (`:204` replaced; FE gives each layer an accurate target, Eq. 14). Everything else verbatim: `compute_ks` keys (`:196`), `repeat_interleave` (`:203`), projector `P[i]`, cache, `L2`, the fp32 CPU solve, cast and in-place add (`:205–217`), the post-edit cache update (`:218–220`), the `delta_norms` record (`:213–215`). After each layer's update the wrapper records `ρ_FE(l) = ‖m_8 − cur_8‖ / ‖m_8 − cur_8^{(0)}‖` at the canonical keyed position (`cur_8` read as `:197–201` at layer 8) — FE's Table 5 metric.
4. *Seam mechanism.* The driver rebinds `H.my_edit = dispatch`; `dispatch(hp, requests, P, cache)` delegates **unchanged** to the original `my_edit` whenever `FE_STATE is None` or `H._LAW5_DEFAULT_CTX` is True, else calls `fe_edit`. `run_recipe` reaches it through the global name (`:489`); `run_law5`'s own call (`:433`) runs with `_LAW5_DEFAULT_CTX = True` (`:430`) and so takes the original path. `FE_CALLS` counts `fe_edit` calls. `fe_edit` takes a frozen mode enum `{"fe", "identity"}`; `"identity"` (targets = `zs` at every layer, `cur` at `z_layer`, `resid = tgt / (len − i)`) exists only for inertness check X2-(iii) and is refused inside any recipe.
5. *Departures from the paper, stated.* FE uses MEMIT's λC regulariser (Eq. 4–5); here the harness's null-space-projected ridge solve applies unchanged. FE edits 2,000 items jointly (§6.1); here 24 per arm. FE does not say whether `h_l` is read before or after the earlier layers' edits; the engine convention (recompute after the earlier edits, `memit_main.py:160–169`) is used, which is what lets FE's remaining residual "halve per layer".

### 2.3 Arm I-1 — OverTone objective for the target solve

**What OverTone does (paper).** It replaces each token's cross-entropy (Eq. 1) by `max(D_KL[π_tar^{(i)} ‖ π_θ^{(i)}], ε)` summed over the value tokens (Eq. 2), with `π_tar^{(i)} = λ δ_{y_i} + (1 − λ) π_flt^{(i)}` if `y_i` is that mixture's argmax, else `δ_{y_i}` (Eq. 3); `π_flt` = softmax of the current logits after the top-nσ filter `s_k ≤ s_max − n·std(s) → −∞` (Algorithm 1, lines 7–9), recomputed every step (line 10, "dyn"); the clip is a token-level early stop (§3.1). It reduces to CE at `ε = 0, λ = 1` (Prop. 3.1); its extra cost is O(|V|) per token (Prop. 3.2). Ablation (§4.4, Table 3, LoRA on ZsRE): removing the clip, the dynamic target, the argmax check or the filter each lowers the average.

**This harness's transcription.** `compute_z_overtone(model, tok, request, hparams, layer, context_templates, lam, eps, n_sigma)` in `experiments/track_c/c10x_overtone_z.py`, authored from a `cat -n` of `compute_z.py` (LAW#4): lines `:28–140` and `:151–185` copied verbatim (prompts, lookup, delta hook, Adam, KL term, weight decay, total loss, print, the **engine's stopping rule verbatim** — total loss < 0.05 or 25 steps — clamp, return); only the reduction `:141–149` is replaced:
- `ce` = the engine's gathered negative log-probabilities, computed exactly as `:141–145` in the engine's dtype;
- per scored position (prompt p, position t, label y), under `no_grad`: logits `s = (ln_f(full_repr) @ lm_w + lm_b)[p, t]` in float32 (the pre-softmax of `:140`); keep = `s > s.max() − n_sigma · s.std()`; `π_flt` = softmax over the kept entries; `cand = lam · onehot(y) + (1 − lam) · π_flt`; `π_tar = cand` if `argmax(cand) == y` else `onehot(y)`; all detached;
- `extra = Σ_v xlogy(π_tar, π_tar) − Σ_v (π_tar − onehot(y)) · log π_θ` (float32, cast to the engine dtype), so that `ce + extra = D_KL[π_tar ‖ π_θ]` and `extra ≡ 0` exactly when `π_tar = onehot(y)`;
- `tok_loss = clamp_min(ce + extra, eps)`; `nll_loss_each = (tok_loss · mask).sum(1) / target_ids.size(0)` (the engine's per-prompt mean over tokens, `:149`; the paper sums, Eq. 2 — the mean keeps the engine's balance against KL and weight decay); `nll_loss = nll_loss_each.mean()` (`:150`).
- **Settings (pre-registered):** `lam = 0.1`, `n_sigma = 0.5`, `eps = 0.01` — the paper's FT-M row (App. B.1; LoRA uses ε = 0.05, MELO and WISE n = 1). FT-M, which "fine-tunes a special layer identified by causal-tracing analysis" (§4.1), is the closest of the four to a locate-then-edit target. With ε = 0.01 the clipped mean has floor 0.01, so the engine's 0.05 stop can still fire; steps used are recorded per request.
- **Vectorised** over positions (Algorithm 1 notes the inner loop is parallel); no float64 tensor on MPS (the CORPUS/53 first-attempt halt).
- **Seam:** the driver solves the 72 OverTone targets (A1, A2, A7 × 24, `layer = 8`, same `ctx`) before the recipe and supplies them through `Z_OVERRIDE` keyed `(subject, " " + value)` (`c10e_bandknob.py:97`, `:185–189`); `Z_OVERRIDE_HITS` must equal 3 in this recipe; the override is never consulted in the LAW#5 check (`:186`). Spreading, keys and the layer solve are unchanged.
- **Departures, stated.** The paper fine-tunes parameters with OverTone; here it fits one hidden-state vector per fact over six context prompts plus the KL prompt. The fit at stop is expected below the engine's 0.99 by design (the mixture target puts mass 0.1 + 0.9·π_flt(y) on y once y leads), so the 0.98 fit screen of §2.5 does not apply to I-1; per-token `π_θ(y)` at stop is recorded instead.

### 2.4 Inertness (LAW#5), numeric — any failure → HALT before any write arm

**Tolerance rule (C10S §2; `docs/C10V_LAYERPICK_PREREG.md:58`):** relative L2 `‖a − b‖ / ‖a‖` (fp32), max-abs recorded; tolerance = max(10 × measured floor, 1e-4). **Lesson carried from C10S §7 A2:** fp16 kernels round differently across batch shapes and the 25-step optimisation amplifies it (rel 0.122 there); every parity check below therefore compares *identical batch shapes and identical arithmetic*, so the expected distance is 0.0 and the floor rule applies.

- **G (both arms, every recipe).** The standing harness gate `run_law5` (`:415–446`) INERT inside every `run_recipe` call (`:463`), with `Z_OVERRIDE` and `FE_STATE` unset for its duration.
- **X1-(i) solve floor.** The engine `compute_z` three times for one request (Zorbland, its A7 value) on the same `ctx`; floor = the largest pairwise distance.
- **X1-(ii) reduction parity (Prop. 3.1).** `compute_z_overtone(lam = 1, eps = 0)` against the engine `compute_z` on all 72 requests (A1, A2, A7 × 24), same `ctx`, same process: every returned z within tolerance, and identical step counts. By construction (`extra ≡ 0`; `clamp_min(x, 0) = x` for `x ≥ 0`) the arithmetic is the engine's; a non-zero distance means the copy is not the engine.
- **X1-(iii) active-path structure (the C10S (iv) lesson: identical prompts cannot catch an index bug).** For two requests (Zorbland A7, Zorbland A1) at step 0 (`delta = 0`) and at the stop step, the solver dumps per scored position the logits (top-64 suffice), the keep-mask size, `π_tar(y)`, the mix/skip decision and `tok_loss`; an independent reference in the reader (Eq. 2–3 and Algorithm 1 lines 7–11, written from the paper text, no code shared with the solver) recomputes them from the dumped logits: mix/skip decisions identical, `tok_loss` within 1e-4 relative. Selftest positive controls: a logits vector where y is the top token (the mixture applies) and one where it is not (skip), both matching hand-computed values.
