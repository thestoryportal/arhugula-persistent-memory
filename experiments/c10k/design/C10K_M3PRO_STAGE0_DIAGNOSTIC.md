## 3. Verdict: HALTED - HARDWARE_ENVELOPE

The Stage 0 condition is met: a source-faithful run must execute the 17 hard bindings in the algorithm modules; on this machine the first of them raises before any z-vector is computed (E8), and every one of them would (E2). Removing them is a source change to the algorithm modules, which the prereg classifies as a separate non-official port (item 8). A runtime shim (patching `torch.Tensor.cuda` / `torch.device` from the launcher so the module files stay byte-identical) does **not** rescue a PASS: it changes what executes just as surely as editing the files, and MPS numerics differ from CUDA regardless, so it is a deviation to declare and review. No environment was built beyond the import checks; no `logs/c10k_anyedit_official_upstream_env.json` is emitted; this document, its three logs and the halt record are the Stage 0 artifact.

## 4. I-INFER (labelled; not evidence)

- **Float64 is probably not a second barrier.** No `.double()`/`float64` literal appears on the upstream edit path (grep), but AlphaEdit's projector uses an eigen/SVD decomposition and dtypes can enter via hparams or `layer_stats` defaults. Nearest test: E11 — the SVD runs on the MPS device at the 3B width; that shows the op exists on MPS, not that upstream's 7B-width path survives it.
- **The VRAM half of the envelope probably binds too, under upstream's defaults.** Arithmetic only (no load test): fp32 Qwen2.5-7B weights ≈ 28.3 GB (7.6e9 × 4 B) + five fp32 18944² projector/covariance matrices ≈ 6.7 GB ≈ 35 GB before activations and the `compute_z` optimisation, against a recommended MPS working set of **37.4 GB** on this machine (`torch.mps.recommended_max_memory()`). Fitting would need fp16/bf16 loading or offload, which are exactly the "local tricks" item 8 excludes from a PASS. The cheapest falsifier is a load-only probe of 7B-Instruct at the upstream dtype; not run (it would pull a 15 GB model for a halt that E8 already settles).
- ~~`memit_ARE` plausibly reduces to MEMIT in a degenerate setting.~~ **Read and refuted** (`docs/C10K_MEMIT_ARE_REDUCTION_NOTE.md`, 2026-10-04): the window loop does collapse, but the solve's `K_p` preservation term, the last-prompt-token keying without templates, and the KL-free objective all survive. Not a degenerate MEMIT.
