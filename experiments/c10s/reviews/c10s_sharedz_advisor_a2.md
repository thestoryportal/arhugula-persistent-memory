## Blocking

**B1 (BLOCKING): the new (iii) is blind to a sum-instead-of-mean reduction, the bug the original (iii) existed for.** `c10s_sharedz_read.py` `triplicate_verdict` (diff +181–191) gates three things. The per-row step-0 NLLs (`nll_each_step0`) come before the reduction, so a `.sum()` at `c10s_sharedz_arms.py:272` leaves them unchanged. Stop reason and step count are the same, because all three solves exhaust the budget either way. The final mean NLL is allowed ±0.01 around 0.014. Under a sum bug the logged final "nll" is 3 × the per-row value, and the bug up-weights NLL against KL and weight decay, so the per-row value falls. Any per-row final in [0.0013, 0.008] lands within 0.01 and passes. My replay: `triple.history` with step-0 nll 25.44 (3 × 8.48) and a final 3 × 0.006 → `triplicate_verdict(...)["ok"] == True`. The prereg's original (iii) wording, "preserves the mean objective exactly", names this guard, and A2 removed it silently.
*Fix:* add `"step0_mean_close": abs(single["history"][0]["nll"] - triple["history"][0]["nll"]) <= tol["tau"]` to `parts` (also gate `history[0]["loss"]`, which at step 0 equals the mean NLL because KL = WD = 0). On the halt data this is 0.0026 against τ 0.033, and a sum bug gives about 17. Add a selftest case with a 3× step-0 history that must fail. Add one A2 sentence: "the step-0 mean NLL (= total loss) within τ of the single solve's".

**B2 (BLOCKING): rounding alone can flip "same stop reason / same steps" because the threshold sits at the end of the budget.** The final total losses are 0.05187 (single) and 0.05087 (triplicate): 0.0009 above the engine's 0.05 stop, about one step's late-phase decrease divided by 5. The (iv) solve stopped by `loss<0.05` at 0.04877 on the same step. In the rerun, `ctx` is re-sampled in-process (`arms.py:572` "sampled unseeded per process"), so whether each trajectory crosses 0.05 on step 24, step 23 or not at all is set by rounding of exactly the size A2 calibrates for. A crossing at it = 24 changes only `stopped_by` and fails `same_stop` (replayed: `same_stop False`, `same_steps True`, `ok False`). A crossing one step apart fails `same_steps`. My rough estimate from the late-phase loss gap (about 0.001) against the per-step decrease (about 0.005) is a spurious HALT on the order of 1 in 5. This is the same failure mode A2 exists to remove.
*Fix:* replace `same_stop` and `same_steps` with `"steps_close": abs(single["loss_evals"] - triple["loss_evals"]) <= TRAJ_CLAMP_SLACK` (or a new `TRAJ_STEP_SLACK = 2`), and record both stop reasons. If a stop-reason gate is wanted, accept a mismatch when the run that did not stop ends with a loss below 0.05 + 0.01. Change the A2 text to match. Add selftest cases: a stop-label flip at the same step must pass, and a 10-step difference must fail.

**B3 (BLOCKING, text-only): (vi) is not computed "on the run's own context templates."** `noise_twin(ctx)` runs in the inertness process with that process's `get_context_templates` sample (`c10s_sharedz_inertness.py:208`). The driver samples its own at `arms.py:592`, and the code itself says context templates "are sampled unseeded per process (CORPUS/44 F-A4)" (`arms.py:572`). The twin's engine z values are therefore not the screen's canonical z values. The noise floor comes from a different context draw (the three historical canonical totals 49/54/51 show the cross-process spread is real). The prereg sentence at A2 (vi), "on the run's own context templates", is false as implemented, and it is the text that will qualify the cell-1 verdict.
*Fix (preferred, no code):* change the sentence to: "on the inertness process's context templates (recorded in `inertness.json` `ctx`; the cell-1 run samples its own, so the twin measures the within-process rounding floor, not the screen's own pairs)". The reader line at `c10s_sharedz_read.py` (diff +400–402) should say "inertness-process ctx". The alternative, moving (vi) into `injection_cell` (it would reuse `z_c`, add only 24 triplicate solves, and run on the screen's own ctx), changes the driver. It would also need a pre-registered rule for a twin that FAILs after the screen data exists, so it is not recommended for this amendment.

## Advisory

**A1 (ADVISORY): attribute the 0.0137 in the halt analysis by test, not inference.** Add one recorded readout to `check_iv`: the function's exact 19-row batch forward with the zero-delta edit hook, under `torch.no_grad()`, compared with `reference_nll_padded_batch`. Bit-equal means the residual is grad mode. Not equal means the hook or the two-layer trace changes the numerics. Record only; no gate.

**A2 (ADVISORY): the positive control should use the per-row minimum, not the mean.** `c10s_sharedz_inertness.py:193` computes `posctrl_mean_abs_diff`, but (iv)'s gate is a per-row maximum. A padding-alignment bug hits only the padded (shorter) rows, so what matters is whether every row can show a one-position misalignment. Record `posctrl_min_abs_diff` and gate `min ≥ 2τ`, or keep `mean ≥ 10τ` and add `min ≥ 2τ`. A one-position shift is the right representative for the alignment class: it is the minimal misplacement, and a padding bug shifts by the pad count, which is at least 1. The KL-slice and lookup classes stay on the exact checks, which is correct.

**A3 (ADVISORY): the twin gate is too permissive at the screen threshold.** `noise_twin_verdict` (diff +202–209) passes when the twin's outcome is CONCENTRATED with |gain| ≥ 6, and when |gain| = 5. Also pre-register how `disagreeing_pairs` is used at cell 1. Recommended: if the real screen's gain ≤ the twin's `disagreeing_pairs`, the reader prints a "within rounding floor" qualifier beside PROCEED. The label stays unchanged.
