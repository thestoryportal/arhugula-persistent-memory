## 1. Architecture: an editor that never sees the evaluation, and a trusted scorer

**Trusted parent (`fence/run.sh`, read-only, hash-pinned).** It allocates the run ID and the handoff folders, runs the editor, waits for it to exit, validates and snapshots the editor's artifacts into the scorer's private input area, then runs the scorer. Both stages use the fixed program interpreter in isolated mode (`python -I`: no `PYTHONPATH`/`PYTHONHOME`, no user site, no startup customisation), absolute trusted script paths, and a minimal deterministic environment (`env -i` plus a whitelist; no credential variables). The scorer is never launched from the editor or with editor-supplied arguments.

**Editor stage (agent code).** It runs `edit.py` under the **editor Seatbelt profile**:
- **Network:** none (`(deny network*)`; `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`).
- **No read access to:** the harness, the fence's `sealed/` subtree, the scorer's private areas, the old sandbox, the program checkout, other temp folders, `~/.config/gh`, or keychain files.
- **No exec of** `/usr/bin/security`.
- **Writable:** only its run folder and its own temp folder.

`edit.py` imports only the **editor runtime** (`fence/editor_runtime.py`, read-only, hash-pinned). It reproduces the harness's import-time setup exactly: `HF_HOME`, the engine on `sys.path`, the `chdir` into the engine root, `resolve_device`, the pad token, and the seed set before the model loads, with offline mode set to 1, not the harness's 0. It then loads the model, the tokenizer, the engine and the covariance caches, and exposes the training facts from **`fence/train_facts.json`**. The program session extracts that file once from the harness and records its hash. It holds the **A1, A2 and A7 arms' subjects and values** (`evaluate()` writes all three, and the A1/A2 guards depend on them), the canonical prompt, the hparams and the edit budget. It holds no PTEST, no locality, generic or frame stimuli, and no country-screen files; those two screen files leave the editor's and the agent's readable set. Nothing the editor needs comes only from evaluation data (advisor round 2, name table). The editor writes, as today, the **absolute changed parameter tensors** (`w[n].detach().cpu().clone()` for each changed tensor, with the existing manifest contract) for all three arms, then exits. The edit budget clock starts before the recipe's top-level code, as today, and counts all three edits.

**Scorer stage (trusted).** It runs the fence-owned **`fence/scorer.py`**, hash-checked together with its whole helper closure, under the **scorer Seatbelt profile**: no network; read access to the harness, loaded by exact filename through an explicit `importlib` file spec after a sha256 check, with no directory reopening and no shared `__pycache__`; read access to the sealed files and the snapshot of the editor's artifacts. It never imports `edit.py` and takes no metric or stimulus override from the artifacts or the environment. It applies the saved tensors with `copy_` (the existing structural, dtype, finiteness and MLP-scope checks; `torch.load(weights_only=True)`; a full restore between arms; LAW#5 before measurement) and runs the existing `_score`/`_measure` path unchanged. All its stdout, stderr, tracebacks and its full `score.json` go to a **private scorer area** with its own temp folder and an explicit write allowance placed after the fence-wide write deny. The agent's run folder receives only a validated projection: the 16 existing summary keys and a fixed success/failure status. Raw scorer text and per-template or per-subject vectors never reach the agent.

**The agent's own session.** The launcher gives the agent an explicit built-in tool allow-list (`--tools`): Read/Edit/Write, Bash, and the installed CLI's Monitor/TaskStop background controls. CLI 2.1.292 has no TaskOutput or BashOutput. The generator derives and pins the allow-list from the installed native CLI's builtin declarations and rejects unknown names before invocation. It excludes WebFetch, WebSearch, any browser or Chrome tool, Agent/Task and any external tool entrypoint, with an empty strict MCP configuration (`--strict-mcp-config`). The probe confirms the exact builtin inventory and an empty MCP list. Safe mode may list builtin plugins, including cc-plugin-agents-md, cc-plugin-telemetry and cc-plugin-plugin-authoring; none may contribute a tool. Empty plugin metadata is not required. The Bash sandbox gets an explicit fail-closed network configuration (no outbound, no localhost, no unsandboxed fallback), tested with the exact launcher flags. File-tool and Bash denies cover the harness (worktree and main paths), `sealed/`, the private scorer areas, the old sandbox, the program checkout, foreign temp/capture folders, with an explicit short private own-capture exception (§4), `~/.config/gh` and keychain files. The fence's broad read allowance (`sandbox_settings.py:62,155,200`) is replaced by an explicit whitelist of the wrapper, profile and settings files the agent needs. `claude` itself starts from a cleaned environment (`env -i` plus a whitelist, its own auth left working).

**Keychain.** The run profiles deny the keychain service lookup (a Seatbelt `mach-lookup` rule) as well as `/usr/bin/security` and the keychain files. If a layer cannot make a keychain query fail, the record states the narrower claim, and §5.2's "every attempt fails" is not declared met.

**What changes on the measurement path.** `prepare.py` becomes `editor_runtime.py` + `scorer.py` + the parent's dispatch; the harness and the engine are unchanged. LAW#3 (§3) checks that the new plumbing measures exactly what the old one did.

**Fix round 1 runtime/capture note (verification pending).** Store the fully resolved interpreter and virtualenv paths. Because the resolved base interpreter under `-I` omits virtualenv packages, the trusted editor bootstrap and verified scorer add the pinned virtualenv site-packages before runtime imports. The profiles grant data reads to the root literal `/` and metadata reads to necessary ancestor literals; they grant no new ancestor subtrees. Scorer closure verification also receives exact-file grants for the pinned sandbox ignore files.

The installed native CLI limits its per-uid child temp path to 44 bytes for socket support; longer paths fall back to `/tmp/claude-UID` despite CLAUDE_CODE_TMPDIR. The §4(a) fallback uses a fresh 0700 base `/private/tmp/c10r-<12 hex>` and its sole own child `claude-UID` (41 bytes at uid 501). Set CLAUDE_CODE_TMPDIR to the base, TMPDIR to the child, and grant only the child in Bash/file-tool policies. Foreign shared captures remain denied under both spellings. No relocation claim is made until the scripted probe reports the actual Bash TMPDIR, completes own-temp cleanup, and reads the output file returned by its background Bash call.

## 2. Look-alikes: what is mechanical and what is not
- **No refusal the agent can query.** The 3-gram refusal is removed; nothing tells the agent that a phrase matched.
- **Program-side tripwire, silent to the agent.** `fence/run.sh` archives every `edit.py` it dispatches, with its sha256, to a program-readable archive, because run folders are named `nocommit` and the program side cannot run git on the sandbox repository. The program's audit (`audit_transcript.py`, bound to the new session ID and transcript, the new repository path, the own-capture folders and the private scorer paths) scans every archived `edit.py` and the agent transcript. It looks for each held-out template verbatim and for every 4-word window of each, after the subject slot and punctuation are normalised, with the tokenisation pinned in the code. A hit, a missing watcher or transcript, or an unparseable record invokes the stop procedure (pause the loop, report to the operator). It fails closed.
- **Its stated limit.** It catches copying, not paraphrase. The four known look-alikes (the experiment 3 Q1/Q2 mirrors, the experiment 8 Q3 mirror, the old `DEV_PROMPT`) share no 4-word window with the templates and are **not** flagged; the record says so. From the reseal on, author-blindness carries the rest: the agent cannot read the templates, its new session has no memory of them, and the base carries no prompt derived from them.

## 5. Verification before launch (all required)
1. **Offline:** the tripwire flags each verbatim template and every 4-word window of each, records that the four known look-alikes are not flagged (the stated limit), and passes the cleaned base. `editor_runtime.py`'s import graph reaches nothing that holds `PTEST`. `train_facts.json` holds all three arms and no evaluation stimulus.
2. **Adversarial recipe probe (no model):** a program-controlled fixture runs the same trusted dispatch and policy paths. An inert fixture replaces the MPS preflight and model load, and the agent cannot select it in production. A hostile `edit.py` runs far enough to attempt: file reads of the harness, sealed files, scorer areas, old sandbox, program checkout, a late-created foreign temp folder, `~/.config/gh` and keychain files; namespace introspection of everything it imported; a connection to 127.0.0.1:9222; `git`/`gh` access to the program repository; `security` and a keychain lookup. Every attempt fails. A positive control shows that a harmless artifact is accepted and its result appears only through the summary projection. Dying at a missing import or at preflight is not a pass.
3. **Direct profile tests:** a dummy module loads by exact file under a directory-denied, file-allowed profile, and the scorer profile reads the sealed files. The editor profile can do neither.
4. **Scripted probe agent** (`claude` with the exact launcher flags/settings, `-p`, explicit program-session opt-in, 900-second timeout): a benign fixture prompt specifies exact named Bash commands and Read calls on named paths. It exercises denials for harness/program/sealed/private/foreign-capture/credential/keychain paths and localhost, plus git/gh/security commands. It also reads public files, edits the existing edit.py, writes an own file, creates/reads/removes own temp, uses a heredoc, runs the inert fixture wrapper, reads its actual background output and uses Monitor/TaskStop. The evaluator matches raw tool_use/tool_result pairs and filesystem state; agent prose or refusal establishes no verdict. Missing commands/results/models, malformed streams, startup failures and non-permission errors are FAIL. Record each tool call's actually served assistant.message.model and retain result.modelUsage, including fallback models. The inventory must be the reviewed builtin set, no plugin-contributed tools, and an empty MCP list.
5. **GPU, by the program session:** LAW#3 bitwise through the new plumbing (§3), then the cleaned base's score.
6. Codex PROCEED on the implementation and the probe record.

## 6. What this restores, and what it does not
It stops further exposure: from the reseal on, the agent cannot read the templates, and copying is caught. It does **not** make the three templates a promotion set. They remain the loop's selection metric, and loop output stays a register candidate. **Promotion of any loop result needs a separate, pre-registered held-out set** that was never used to select a recipe and that its authors never saw. Building that set is its own decision.
