## 2. Complete closed wire grammar — R1/F1

### 2.1 Notation, primitive types and universal presence rules

The following is a type grammar for JSON, not executable code. `Type {field: Type,...}` lists EVERY field of that object. Every listed field is REQUIRED; every unlisted field is FORBIDDEN, at every depth. A union selects exactly one form by its discriminator; fields of other forms MUST be absent. No implicit optional fields, defaults, coercions or extensions exist. Constant quoted strings and enumerations are JSON strings with exactly the listed vocabulary. Duplicate keys, non-finite numbers, malformed UTF-8 and unknown versions are rejected. Integers exclude booleans. Validate raw JSON keys before constructing objects.

| Type | JSON type and allowed values | Null / empty semantics |
|---|---|---|
| `Bool` | boolean, `true` or `false` | null/string/list forbidden |
| `UInt` / `Pos` | integer 0..9007199254740991 / 1..9007199254740991 | null/string/list forbidden; 0 is a measured zero only for UInt |
| `Percent` | integer 0..100 | null forbidden unless `Percent?`; zero means parsed 0% |
| `ID` | string, 1..128 characters, no C0/DEL controls, non-whitespace | null, empty string/list forbidden |
| `Text` | string, 1..4096 characters, no C0/DEL controls, non-whitespace | null, empty string/list forbidden |
| `Words` | string, 0..4096 characters, no C0/DEL controls | empty means an explicitly empty recorded text; null/list forbidden |
| `Command` | string, 1..8192 characters, no C0/DEL controls | null, empty string/list forbidden |
| `Path` | string, absolute POSIX path, 1..4096 characters, no C0/DEL controls | null, empty string/list forbidden; never a reader instruction |
| `UUID` | string, canonical lowercase `8-4-4-4-12` hexadecimal UUID | null, empty string/list forbidden |
| `Hash` | string, exactly 64 lowercase hexadecimal characters | null, empty string/list forbidden |
| `UTC` | string, real UTC date/time exactly `YYYY-MM-DDTHH:mm:ss.sssZ`, seconds 00..59 | null, empty string/list forbidden |
| `SessionName` | string, 1..128 characters, no C0/DEL controls, no colon, non-whitespace | null, empty string/list forbidden; passed as ONE argv element, never shell-expanded |
| `T?` | the stated type T OR JSON null, only where explicitly written | null has the field-specific meaning below; empty is still subject to T's rules |
| `List<T>` / `Nonempty<T>` | JSON array, 0..1024 / 1..1024 entries of T | null/string forbidden; List empty semantics enumerated below; Nonempty empty forbidden |

Objects cannot be null, strings or lists unless an explicit union says so. Empty objects are forbidden: even NOT_OWNED contains its discriminator. Constant `null`, `[]`, `true` and `false` are the exact JSON value and type, not optional placeholders. Direct entry IDs (including Subject.id for run/task/session/job entries), dependency IDs, store IDs, physical disk IDs and resource PIDs are unique in their respective lists; repeated Receipt owner subjects and repeated provenance observations are not distinct entry IDs; dependency validation uses exactly the source-owned Queue.items in this same Record (§2.4), with no cycles. An envelope cap bounds total nesting/data; reject nesting deeper than 32 JSON container levels as BAD_VALUE rather than accepting partial data.

### 2.2 Envelope, record, ownership and components

`Envelope {envelope_version: 1, record_utf8_b64: Base64, hmac_sha256: Hash}`. Base64 is a nonempty JSON string of canonical padded RFC-4648 standard-alphabet base64, no whitespace; decoded bytes must be nonempty UTF-8 JSON. Null, empty string/list, URL alphabet and noncanonical padding are forbidden. HMAC-SHA256 covers exact decoded bytes with the commissioned per-source key. No pane text, secrets, transcripts or credentials go on the wire. Serving/copying cannot resign or change those bytes (`B/dashboard_host_status_record_v1.md:45,84–86`).

`Record {schema_version: 3, source_host: Host, collector: Collector, sequence: Pos, source_observed_at: UTC?, writer_at: UTC, views: Views}`. sequence strictly increases only on newly committed publication within this incarnation; writer_at is sampled after collection/record preparation immediately before final serialization/publication, never at serving/copying. PID alone never identifies an incarnation (`B/dashboard_host_status_record_v2.md:40–42`).
`Host {role: "m3"|"intel", host_id: UUID, label: Text, platform: "macos-arm64"|"macos-x86_64", boot_id: UUID}`; role/platform pair is m3/macos-arm64 or intel/macos-x86_64 and must match the commissioned registry. Label is display only.
`Collector {generation_id: UUID, generation_number: Pos, pid: Pos, started_at: UTC, source_sha256: Hash, profile_sha256: Hash}`; generation_number is host-wide, survives boots, and is never a PID or timestamp order (§3).
`Views {m3_science_maestro: M3View, intel_support: IntelView, storage_transfers: StorageView}`.
`NotOwned {state: "NOT_OWNED"}`; no components/payload/reason field. m3 owns M3View and StorageView; intel owns IntelView and StorageView. Its other view MUST be NotOwned. An owned view cannot be replaced by NotOwned or an empty payload.
`M3View = NotOwned | {state: "OWNED", components: {science: Component<Science>, maestro: Component<Maestro>, queue: Component<Queue>}}`.
`IntelView = NotOwned | {state: "OWNED", components: {builders: Component<Builders>, research_engine: Component<ResearchEngine>, resources: Component<Resources>, queue: Component<Queue>}}`. Intel owns its queue/session view; it does not publish M3's queue. Intel Queue.sessions represents every local discovered `codex*`, every assigned session and every registered support session, including RE and sessions without build Tasks.
`StorageView {state: "OWNED", components: {disks: Component<Disks>, folder_sizes: Component<Folders>, transfers: Component<Transfers>, warnings: Component<Warnings>}}`.
`Component<T> = {state: "CURRENT", observed_at: UTC, payload: T, provenance: Nonempty<Provenance>} | {state: "LAST_KNOWN", observed_at: UTC, payload: T, provenance: Nonempty<Provenance>, reason: Text} | {state: "UNAVAILABLE", observed_at: null, payload: null, provenance: [], reason: Text}`.

CURRENT means successful collection, subject to reader freshness. LAST_KNOWN retains the original payload/time and is historical even inside the threshold. Its source provenance must belong to the same enclosing collector generation: across reexec the reader retains older-generation data as historical context outside the new record, never relabels old provenance as new. UNAVAILABLE means no successful payload supplied; the literal nulls/empty provenance are required and do not mean idle. `source_observed_at` is the minimum observed_at of all CURRENT owned components, exactly; null iff none. This null is permitted only there, not an empty time string. Partial collection failure affects that component and dependent claims, never invents a fully idle view (`B/dashboard_host_status_record_v1.md:25,29,49`).

### 2.3 Provenance, subject and original receipts

`Subject {kind: "RUN"|"TASK"|"SESSION"|"TRANSFER"|"RE_PUBLICATION"|"R2", id: ID, generation_id: UUID, host_id: UUID, boot_id: UUID}`. This is the original source subject generation, NEVER substituted by collector generation. `Origin {role: "m3"|"intel", host_id: UUID, boot_id: UUID, collector_generation_id: UUID, collector_generation_number: Pos}` represents a dated observing incarnation.
`Provenance = {kind: "file", host_id: UUID, boot_id: UUID, collector_generation_id: UUID, collector_generation_number: Pos, observed_at: UTC, subject: Subject?, path: Path, sha256: Hash} | {kind: "process_inventory"|"session_inventory"|"pane_capture", host_id: UUID, boot_id: UUID, collector_generation_id: UUID, collector_generation_number: Pos, observed_at: UTC, subject: Subject?, command: Command, observation_sequence: Pos}`.
`Receipt {path: Path, sha256: Hash, measured_at: UTC, subject: Subject}`; no optional/null/empty fields. A receipt is a pointer and hash of saved original evidence, not content verification by the dashboard. Reader NEVER follows received paths.

Every provenance host_id/boot_id/collector tuple must equal the enclosing Record's tuple, including generation_number. Its observed_at must equal the component's observed_at: multi-probe observations use the earliest successful capture time as their common batch stamp, only after every required probe succeeds. A subject, when non-null, must match an actual subject in that payload in kind/id/generation/host/boot. Null means host-level inventory/file observation, not unknown run identity. Every identified run/task/transfer and RE publication requires a matching non-null file subject provenance entry from its authority source; inventory-only provenance cannot establish original job identity. Asserted live processes also require local process_inventory; BUSY/WAITING/IDLE require session_inventory and pane_capture at the same batch stamp. MISSING needs successful session inventory, not a fictitious successful capture; UNAVAILABLE must not cite a failed capture as successful provenance. Repeated session identity at the same observation time across components must agree on process/activity. Provenance mismatch in any part rejects the record as PROVENANCE_MISMATCH.

Each Receipt.subject must equal its containing evidence owner's Subject, except a transfer's source_manifest, whose subject equals source_subject. Receipt.measured_at is original evidence time, no later than that component's observed_at; never renewed by transport. An Origin referring to a remote transfer endpoint is explicitly dated remote evidence, checked against the registry and its own job subject, not falsely equated to local envelope provenance. An unavailable identity cannot have a live process or matching-current provenance claim (`B/dashboard_host_status_record_v1.md:31,35–39`).

### 2.4 Process, activity, tasks and science

`Process = {state: "PRESENT", host_id: UUID, boot_id: UUID, pid: Pos, started_at: UTC, executable: Path, command: Command} | {state: "ABSENT"} | {state: "UNAVAILABLE", reason: Text}`. PRESENT host/boot equal envelope; start <= observed_at. ABSENT needs validated positive inventory. Failed inventory is UNAVAILABLE, never ABSENT.
`Pane {pane_id: ID, pid: Pos, dead: Bool, current_command: Text}`. pane_id must match `%` followed by decimal digits. IDs/PIDs are locally inventoried, no transmitted raw screen.
`Activity = {state: "BUSY"|"WAITING"|"IDLE", observed_at: UTC, pane: Pane, context_left: Percent?, finished: Bool} | {state: "MISSING", observed_at: UTC, context_left: null, finished: false} | {state: "UNAVAILABLE", observed_at: null, context_left: null, finished: null, reason: Text}`. pane exists only for BUSY/WAITING/IDLE; reason only for UNAVAILABLE. context_left null means not parsed, never 0%. finished true only in IDLE from the source classifier's READY/HANDOFF recognition, not science completion. activity time equals component batch stamp; unavailable nulls identify a failed capture. Session PID or observed selected-pane disagreement yields UNAVAILABLE/PANE_IDENTITY_CHANGED, not IDLE. Capture always addresses the resolved pane ID, so an unobserved A→B→A selection change cannot change its source. Any source Context signed-decimal percentage token outside 0–100 yields Activity UNAVAILABLE/CONTEXT_OUT_OF_RANGE, with null time/context/finished and no pane; a malformed wire Percent instead refuses the record as BAD_VALUE.
`Session {subject: Subject, name: SessionName, process: Process, activity: Activity, recorded_task_id: ID?, recorded_state: "running"|"needs_you"|"in_review"|"ready"|"blocked"|null}`. Subject.kind SESSION, host/boot local. recorded_task_id/state both null iff session has no recorded queue task; otherwise both present/non-null and match this Record's source-owned Queue.items. These nulls mean unrecorded intent, not idle. A local discovered session has an inventory-established Subject generation even without file Task authority; process/session/pane provenance suffices for that SESSION, never for a TASK. Activity is separate source-owned observation.
`Estimate {low_min: UInt, high_min: UInt, set_at: UTC}`; low<=high. `Estimate?` null means no estimate; set_at<=writer_at.
`Task {subject: Subject, title: Text, summary: Words, who: Text, recorded_state: "running"|"needs_you"|"in_review"|"ready"|"blocked", session_name: SessionName?, started_at: UTC?, estimate: Estimate?, depends_on: List<ID>, blocked_by: List<Text>, needs_from_you: List<Text>, notes: List<Words>}`. Subject.kind TASK, local host/boot. session_name null means no assigned session; started_at null means start not recorded, never inferred. Empty depends_on/blockers/needs/notes means explicitly none. Empty note text and empty summary are retained recorded text. State is intent, never live activity. These vocabulary and queue attributes preserve the opened source (`tools/dashboard_queue.py:28–32,44–64,148–155`).
`Run = {identity_state: "IDENTIFIED", subject: Subject, source_directory: Path, source_sha256: Hash, prereg_sha256: Hash, state: "RUNNING"|"HALTED"|"DONE"|"FAILED"|"INCOMPLETE"|"INVALID"|"NOT_RUN", process: Process, evidence: Nonempty<Receipt>} | {identity_state: "UNAVAILABLE", run_id: null, run_generation_id: null, reason: Text}`. IDENTIFIED Subject.kind RUN, local host/boot; RUNNING requires PRESENT process and validated source authority. Missing/invalid/unfinished terminals cannot map to DONE; preserve their explicit status. Source vocabularies need reviewed deterministic mapping into these wire values; no guessed status. Null IDs occur ONLY in UNAVAILABLE and mean identity not established.
`Science = {state: "RUNS_OBSERVED", runs: Nonempty<Run>, inventory_validated: true, source_reads_validated: true} | {state: "NO_ACTIVE_RUN_OBSERVED", runs: [], inventory_validated: true, source_reads_validated: true}`. NO_ACTIVE requires all required inventory and source reads positively validate no active run. Failed checks require Component UNAVAILABLE; no false booleans or empty RUNS_OBSERVED permitted. A RUNS_OBSERVED containing unavailable identities cannot grant a current run claim.
`Maestro {sessions: List<Session>}`. Empty means successful required inventory found no registered sessions, not collector failure.
`Queue {source_path: Path, revision: ID, sha256: Hash, edited_at: UTC, items: List<Task>, sessions: List<Session>, pending_decisions: List<Text>}`. source_path mismatch refuses SEMANTIC_INVALID; source_path equals the commissioned absolute source-host `docs/program_state.json` path (Intel has its own reviewed local queue file). Empty items/sessions/decisions are validated none; edited_at remains original file time. Both hosts include the union of assigned queue session names, discovered local `codex*` sessions and registered MAESTRO/support sessions, irrespective of Tasks/builds. M3 owns M3View.queue/maestro; Intel owns IntelView.queue. Session names and subject IDs are unique within Queue.sessions. Activity comes from source-owned capture; the opened queue includes named plus discovered `codex*` targets (`tools/dashboard_queue.py:535–549`).
Task dependency scope: M3 Task.depends_on IDs resolve only against M3View.queue.payload.items in this same M3 Record; Intel Task.depends_on, including Builder.task, resolves only against IntelView.queue.payload.items in this same Intel Record. Never against a remote, cached, merged or client queue. Builder.task must equal the entire corresponding local Queue Task. A Task or recorded Session reference with absent queue item, unavailable Queue authority or cross-host reference refuses the entire record as SEMANTIC_INVALID; never drops the dependency or calls it ready. Duplicate IDs and cycles, including self-cycles, also refuse SEMANTIC_INVALID. An unrecorded Session with both recorded fields null needs no Task and remains legal when Queue.items=[].
`Builder {task: Task, process: Process, activity: Activity, base_sha256: Hash, source_sha256: Hash, package_sha256: Hash, stage: "QUEUED"|"BUILDING"|"TESTING"|"IN_REVIEW"|"DONE"|"HALTED"|"FAILED", receipts: List<Receipt>}`. Empty receipts means none saved, not proof of success; DONE requires a nonempty receipt list. If Task.session_name null, Activity must be UNAVAILABLE with reason; not IDLE. `Builders {jobs: List<Builder>}`; empty requires positively validated no support jobs.

### 2.7 Deterministic reader outcomes and example contract

ACCEPT means a validated record is admitted with its component states, NOT that LAST_KNOWN/UNAVAILABLE becomes current. Entire-record refusal shows UNAVAILABLE and a reason code; retained data is historical with advancing age. A component freshness failure shows that component UNAVAILABLE/STALE_COMPONENT, retaining original source time/age; other valid components remain independently attributed. Do not update its last-success time. No rule silently truncates data or substitutes idle/zero/completed. Only exact final verifier OK establishes current-feed success; a durable prepared high-water transaction whose OK fails remains conservative history, not a success/lease/age reset.

Validation order and first-failure codes: transport failed/no response → TRANSPORT_FAILURE (successful empty body goes to BAD_JSON); bytes >MAX_ENVELOPE_BYTES → OVERSIZE_ENVELOPE; malformed envelope JSON/UTF-8 → BAD_JSON; duplicate keys → DUPLICATE_KEY; envelope unknown/missing/type/version/value checks → UNKNOWN_FIELD/MISSING_FIELD/WRONG_TYPE/UNKNOWN_VERSION/BAD_VALUE; base64 → BAD_BASE64; decoded cap → OVERSIZE_RECORD; record JSON → BAD_JSON/DUPLICATE_KEY; signature → BAD_SIGNATURE; record grammar → UNKNOWN_VERSION/UNKNOWN_FIELD/MISSING_FIELD/WRONG_TYPE/BAD_VALUE/OUT_OF_VOCABULARY/CONDITIONAL_FIELD (in that precedence, ties by lexicographic JSON Pointer); registry/hash ownership → IDENTITY_MISMATCH; metadata validation → READER_STATE_MISSING/READER_STATE_CORRUPT/TRANSITION_UNVERIFIED; generation and sequence → OLD_GENERATION/TRANSITION_UNVERIFIED/GENERATION_CONFLICT/SEQUENCE_REGRESSION/SEQUENCE_CONFLICT; provenance/semantic relationships → PROVENANCE_MISMATCH/SEMANTIC_INVALID; clock → CLOCK_UNVERIFIED/BAD_TIME; freshness → STALE_COMPONENT. Depth >32 is a raw-record container precheck before field validation (after signature/caps) and uses BAD_VALUE. Wrong same-type non-string constants use BAD_VALUE; unlisted string discriminators/constants use OUT_OF_VOCABULARY. Base64 format/empty-string failures use BAD_BASE64 after its JSON string type check. Local payload subject/process/remote-origin host/boot mismatches use PROVENANCE_MISMATCH; owner-kind, accounting and state relationships use SEMANTIC_INVALID. Source-authority controls test known original observations at collection, never reader traversal of Receipt paths. Missing/present union-only fields use CONDITIONAL_FIELD, not MISSING_FIELD/UNKNOWN_FIELD. Null in a nonnullable field, non-null in a null-only field, or a non-list in a literal [] field is WRONG_TYPE. Empty nonempty-type strings/lists or nonempty literal-[] lists are BAD_VALUE. Envelope HMAC authenticates bytes before their record fields are USED, even though JSON syntax may be inspected first. A no-input reader with absent/corrupt metadata is immediately UNAVAILABLE/state reason without waiting for a poll. Discriminators are unconditional required fields; if missing/invalid, do not guess an arm or emit invented child failures. Validate only fields admitted by the selected arm; do not traverse forbidden fields, wrongly typed containers or non-null replacements of null-only fields. Pane ID string-format failure is grammar BAD_VALUE. Envelope malformed Hash syntax is BAD_VALUE before signature verification.

`B/dashboard_record_v3_examples.json` contains literal schema-3 base records/envelopes and matching fixture-state hashes, including Intel queue and resolved-pane provenance.
