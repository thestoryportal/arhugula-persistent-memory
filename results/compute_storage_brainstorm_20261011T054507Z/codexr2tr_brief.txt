== What TR does ==
1. Parse the in-scope Python with ast; resolve module aliases (import c10w_oracle_read as R, etc.) and in-repo calls across modules. Parse the shell scripts conservatively: every command line that starts a program is a site; any construct you cannot parse (eval, variable command names, sourced files) is UNRESOLVED, never dropped.
2. Process-start primitives: subprocess.run/Popen/call/check_call/check_output, os.system/exec*/spawn*/popen/fork, plus any function that transitively reaches one (computed, not hand-listed).
3. From each entrypoint's argv dispatch (stage/phase/mode), compute every path to every site. Treat a branch or loop as data-selected when its predicate, iterable or operand depends on loaded data: json/file reads, Path.exists/is_file/glob, latest_directory, argv, os.environ, stdin, or a value written to disk and read back. A branch is excluded only when pinned code on the path, reached before the spawn, makes it unsatisfiable (for example a require() on the same value). When you cannot decide, it is reachable.
4. Per site: count kind (pinned_constant with the enforcing line, or loaded_data) and operand source (pinned_literal with line, or loaded_data with the record/field).
5. Every call TR cannot resolve (getattr, dynamic dispatch, callables from data, out-of-repo callee) is listed as UNRESOLVED with file:line. Out-of-repo libraries (torch, the engine) are boundaries, listed by name.
6. `--against <profiles.json>`: for every (profile, reachable site family), report REPRESENTED (the child or binding), REFUSED (the refusal) or GAP. Exit 1 if any GAP, exit 0 otherwise; always print UNRESOLVED counts.
7. Output JSON (sites, paths with file:line chains and taint reasons, unresolved, boundaries) to stdout or --out; no other file writes.
