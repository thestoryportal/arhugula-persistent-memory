## 3. Top three recommendations (review steps only; hold unchanged)

1. **Review failure-to-status mappings first.** First reversible step: MAESTRO compares failed inventory, empty valid inventory and malformed transcript cases on paper with the displayed words; no runtime change. Worth-it criterion for a later authorized fixture: failed observations say UNAVAILABLE, valid empty inventory alone says no work, and parse errors remain visible. Displaces silent empty/default observations in Active/helpers, not the shared detector (`tools/dashboard_tile.py:31`, `tools/dashboard_active.py:25`, `tools/dashboard_subagents.py:36`); applies checklist rules 11–14.
2. **Check the phone's first visible answer.** First reversible step: obtain read-only host captures of all eight tabs at the operator's actual Termius dimensions, then ask which work needs attention; use existing views, no mockup/build. Worth-it criterion: urgent action and unavailable status are visible without rotation, a headline answer within five seconds, and no helper row exceeds pane width. Five seconds is a trial threshold adapted from [Sisense][Sisense]. Displaces fixed helper columns and reliance on automatic rotation if a later change is approved (`tools/dashboard_subagents.py:188`, `tools/dashboard_report.py:96`); duplicates neither queue's attention reservation nor its width guard (`tools/dashboard_queue.py:329`, `:356`).
3. **Review LabViz against its existing contract before expanding it.** First reversible step: compare the current review receipt with the spec's phone, contrast, caption, source and task criteria; missing receipt fields stay UNVERIFIED. Worth-it criterion: an approved later browser review supplies measured 360/390px layouts, ≥13px rendered labels, ≥16px body text, required contrast and correct source drill-through, plus one operator explanation of result/goal/caveat. Displaces a second design checklist/toolchain; uses `docs/LABVIZ_V2_SPEC.md:405`, `:407`, `:409`, `:413` and `tools/labviz/README.md:28`. No browser review or build is authorized by this report.

## 4. Ideas worth borrowing even from SKIP items

- UW: a shared overview matters; adapt shared access to the frozen local status record, not experiment-time hypothesis changes. [UW][UW]; `CONTEXT.md:16`.
- RIB: cache slow-changing facts and keep metric formatting consistent; do not refresh everything at live-process frequency. [RIB][RIB]
- Julius: outside-reader explanation and equal-scale comparisons are useful; its upload/AI service is unnecessary for these checks. [Julius][Julius]
- Reject universal chart/widget-count limits, “real time guarantees accuracy,” and persuasion-first storytelling; preserve the recorded limitations. [Sisense][Sisense], [RIB][RIB], [FedTech][FedTech]
