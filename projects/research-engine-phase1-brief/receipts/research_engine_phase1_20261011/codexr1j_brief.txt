== Design decisions already made (MAESTRO) ==
R1, publish only durable bytes: the positive receipt must never appear under the `<prefix>.final` name until its bytes are already durable, so no later corrective write is needed to invalidate it. Write the canonical final JSON line to `<prefix>.final.pending` with O_CREAT|O_EXCL, flush, fsync the file, fsync the directory. Then take a fresh M3 clock reading; only if it is ≤ the deadline, `os.link(pending, final)` (fails if `.final` exists; no overwrite) and fsync the directory again. Any error or crash before the link leaves no `.final`, so authority is absent by construction. A `.final.pending` file is never authority under any reading (bind, `require_anchor()`, successor acceptance, `qualified()`), and its bytes are charged to receipts like every other companion (add its pattern to v9's receipt list). If the directory fsync AFTER the link fails, do not unlink or rewrite anything: exit nonzero and record the failure, and state in the report exactly what remains (file content is durable; only the directory entry's durability is uncertain) as an explicit narrowing for Astra to rule on. The stderr rejection marker may stay as extra evidence but no acceptance path may depend on it. `.exit` stays written once, never rewritten.
R2, enforce the cutoff inside binding: the stub passes the Intel cutoff (T0 + budget, in time.monotonic() terms, the same T0 it already reads first) into the binder.
