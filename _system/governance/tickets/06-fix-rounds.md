# Stage 6 — Fix rounds (after `blocked`, `halted`, or a NO-GO)
Part of the tickets guide. Router: `_system/governance/TICKETS.md`. Roots (L, M, S, W, TD, MEM, HO): `00-roots-and-roles.md`.

Review gets one round (S/SKILL.md:88-95, S/references/reviewer.md:12-18). MAESTRO rules on each NO-GO in `TD/reviews/<T>/RULING.md`: it accepts or rejects each finding and names the kill set by mutant id (M01...). Survivors outside the kill set are out of scope. A tests-only fix is verified by MAESTRO itself (the reviewer's reproduction and each mutant in the kill set); a second Astra round is only for a fix to a hook that gates every commit, or a fix that rewrites a check [R38]. A pre-review NO-GO also returns to a ruling and a fixer before Astra ever runs (ship.sh:73-74).

- The fix brief is `TD/brief-<T>-fix<n>.md`, copied from `L/w1opt/brief-template-fix.md` and filled in (kill set reproduced first, ruled edits only, each new test shown to fail with its code disabled, the tool family's suites in parallel (at most 4, each with its own TMPDIR), the ticket test once, no fixer gate (the re-ship's gate 1a runs master's tool on the same base), the 45% handoff, the self-matching `pgrep -f` wait forbidden, a capped reply). The older `L/tools/template-brief-fix.md` is T020-specific; do not start from it [G8]. A fresh fixer per round.
- Before you write a fix brief (the T330 rounds, 2026-10-17; operator: "Apply these learnings to any next fix round durably and seamlessly"):
  - Stage the review's own probes as the acceptance. Each finding of the form "requirement disabled, the test still passed" (probe.md `R(n)` rows, a reviewer's mutant) is reproduced by you on a sample, then named in the kill set; the fix is done when every staged probe fails. Two builders converged in one round that way (MEM/deletion-probe-review-staged-acceptance.md) [R56].
  - Each always or never clause of a ruling names the exact check it covers and the case it must not touch. T330 ruling 4 said "every refusal" where it meant the refusals inside a run; the fixer found the final-scan case and note 1 had to narrow it. Narrow or correct a ruling in a new note file, never by editing it (MEM/ruling-scope-precision.md) [R57].
  - A hand edit of a ticket (a wider write list, a new dep) is followed by `tickets.py check TD/tickets --base /Volumes/memit/llmdb-lanes/base` before the ship. T330's ruling-1 write list gained a file that T328 also writes; the close refused it as two parallel tickets on one file [R14], and the fix (deps T328, land T328 first, fast-forward the lane) cost a second train [R58].
  - Pin the lane's write-list hashes before the fixer starts and again at its hand-back (`TD/reviews/<T>/lane-pre-fix<n>.sha256`), and read `git diff origin/master -- <existing test files>` against the ruled lines before you trust its GREEN [R46] [R57].
  - After a train that changes mutant_ops or guard_mutants, the master tool that gates the next ship is not the tool the fixer ran: expect a different mutant count, and re-run the gate on the lane before you rule a survivor (MEM/regate-lanes-after-operator-train.md) [R59].
  - Stop after round 2. A second NO-GO that brings new gaps goes to the operator as a scope decision, not to round 3 on your own (MEM/sol-for-sweeps-astra-for-gates.md). A review stopped by the content filter is not reworded and relaunched; the operator picks the reviewer (MEM/review-substitution-is-exception.md) [G25] [R60].
  - Make the ticket test an oracle for every clause of each requirement. T330's test ran only its own file, but its R(4) ("every per-run check of today holds for each run") is tested by the whole `test_guard_mutants*.py` family; each probe round found one more untested clause until ruling 12 widened the test to the family (`TD/reviews/T330/CYCLE-PATTERNS.md`). Before you rule, run a clause-deletion matrix against the ticket test, with each mutant asserted to apply once and the controls killed [R61].
  - The fixer sweeps its own new lines and re-runs the reviewers' full mutant tables, each `old` string retargeted to the fixed file and asserted to occur once (template step 3b). All three T330 round-2 findings were lines that fix 2 added; a mutant built from the old file's strings no-ops on a moved line and reads as killed [R62].
  You will have a NO-GO in hand at minute 40 and think *"one finding, one quick fixer."* Read the eight items above first: each one cost a round in plan 318 or 327.
- A ticket whose new mutant changes an existing suite's exact expectations (T319 vs test_guard_mutants_lines.py, T323 vs test_guard_mutants.py) needs a MAESTRO ruling that widens its write list and bounds the edits (`L/w1opt/followup-318/reviews/wave-b/RULING.md`); without it check 1b stops the ship with 5. CI runs none of these suites [G4], so MAESTRO runs all of them on a scratch merge of the ready lanes before the train (`L/tools/combined.sh T...`: an origin/master export plus each lane's write-list files, every test_guard_mutants*.py suite). To reproduce a staged probe, `L/tools/spot.sh T file 'old|new' ...` applies each one-line disable to a scratch copy of the lane's `code/` and runs the ticket test [G31] [G34].
- Rank reviewer NOTEs by "can it lose data", not only "can it give a wrong PASS": a candidate-delete NOTE filed as non-blocking was later reproduced as a lost candidate [R39].
- Several findings of one class in a pre-review NO-GO: rule the class and order a mechanical sweep of the whole file, with the sweep oracle positive-controlled on a known-bad head, instead of one fix per finding and another round per fix [R40].
- A Claude review in place of Astra is a one-off for one named ticket, never a rule and never carried into a handoff as "same for the next step" [R41].
- Never edit a review file after anything pinned it (a verdict, a ruling, a packet): a consumer that hashed it stops on the drift, or worse, trusts a changed record. Add a new note file instead [R43]. Earlier rounds are renamed, not rewritten (`astra-round5.md`, `prereview-round2.md`).
- A lane cut before a dependency merged lacks it. Before a fix brief names a newly merged helper, check `git -C <lane> merge-base --is-ancestor <dep> HEAD`; if not, merge origin/master into the lane first [R21].
- A fixer that reports done while its background work still runs: stop it, then pin the lane hashes before you verify, or you verify a lane that is still changing [R46].
- After a tests-only fix, Astra's frozen mutant trees under `TD/reviews/<T>/work` still hold the old test: tell the next round to rebuild them [R35].
- The fix is committed by re-shipping. You will look at the fixed lane and think *"two files, I'll `git add` and `git commit` it myself."* The classifier denies it, and if it did not, the commit would skip the allowlist check and the ledger. `ship.sh` runs `tickets.py close`, which commits, pushes, and then fails harmlessly at `gh pr create` because the PR exists; ship.sh accepts that when the open PR's branch holds the new head [R7].
- Re-ship arguments: copy SPECREF and SEAM from `TD/reviews/<T>/packet.md` ("Spec and background" / "Seam"), or from `TD/ship-args-<T>.txt`; never rewrite them from memory. A wrong seam points Astra at the wrong boundary [R5].
