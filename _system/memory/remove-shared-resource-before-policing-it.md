R2 (two Macs sharing memit) ran ~14 h and 10+ Astra NO-GOs trying to prove a complete list of every process science could start. The round-13 Sol sweep + AST tracer showed it can never close (Torch/Git/Bash internals untraceable). Fences (sandbox), run-time watch, single-file scripts and tar transfers each fixed only part. The operator cut through it: "Can the Intel Mac pull in its needed context directly from Git on demand instead?" → the initial Git+Drive concept kept memit M3-only (operator GO 2026-10-11 23:02Z, `knowledge/analyses/compute-storage/compute_storage_brainstorm_20261011T054507Z/r2_redesign_operator_ruling.md`). The later adopted v4 (D-R2C-ADOPT) has the M3 push to approved Intel staging and the Intel do Drive uploads, retries and checks; the Intel never accesses memit; the push observes check_gpu and stops when science starts. Design adoption is not activation authorization; activation still needs its separate approval and checks.

**Why:** policing a shared resource requires a complete model of every actor; removing the sharing removes the need for that model.

**How to apply:** when a gate loop finds "one more layer" twice in a row, ask first "can the contention be designed away?" (separate copies, pull-on-demand from the source of truth) before proposing stronger enforcement. Bring that framing to the operator early, in plain words. Related: [[intel-exists-to-offload-the-m3]]; [[sol-for-sweeps-astra-for-gates]] (Claude auto-memory, not _system/memory/).

Second instance (2026-10-14, atomic-ticketizer link binding): SK3h→SK3k took 4 Astra rounds; each found one more CommonMark edge the helper imitated (fences, labels, `<`/`>`, `>` on a next line). It converged when the ruling removed the imitation and failed closed on the construct (RULING-C19: strip only spaces/tabs, let any `>` hit the ambiguity reject), proven by a parser differential plus Astra's own expanded probe as a positive control. Same pattern: do not imitate a complex grammar; fail closed and add an authoring rule.

Third instance (2026-10-14, ICM v2 package B1, v6→v9): T088/T090 wrote new tests INTO the predecessor test files; four rounds froze bytes, then members, then routed verdicts to sealed bytes, and Astra found one more route each time (aliases, `globals().update`, T022/T072 wrappers, the isolation hook blocking the sealed oracle). A fix that "makes X immutable" while X is still shared is still policing. RULING-V9-1 moved successor tests to new modules and froze the predecessor files whole. Lane F hit the same shape with drifting live files: fold measured-volatile sources into the existing refresh-after-drain rule (F-R4b) rather than recut or hold.

Fourth instance (2026-10-14 22:57, v10 B1): V9-1 split the files, but gate `verify` commands still ran in the worker worktree where successor files sat beside predecessors, so a computed import beat the static scan. The verifier's own case runs already excluded successors. Check WHERE each verdict-producing process runs, not only what its code imports. RULING-V10-1: predecessor tests run in a successor-free copy via one package runner; product-tamper ruled out of scope (return review).
Cost check: a design-away ruling that copies or fetches data must name a size bound. V10-3(b) "fetch objects reachable from BASE" was ~6 GB per gate run; V10-4 replaced it with Git alternates (257 B). Measure the data before ruling a copy.
