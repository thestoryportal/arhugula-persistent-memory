**Fence lessons that generalize:** Claude Code's Bash sandbox denies every `sysctl` read, so PyTorch MPS silently falls back to CPU inside it — model runs need wrappers listed in `excludedCommands` by exact absolute path, called BARE (no `&&`, `;`, `&`, redirect, cd) or they stay sandboxed (exit 71). The Bash sandbox does not cover the Read tool (use `permissions.deny: Read(//abs/path/**)`); a file-tool deny always beats a nested allow. Every runtime allow-list entry is a history route until you open it and read what it holds. Probe the fence in a disposable `claude -p` session with the exact launch flags after any path change.

**Why:** the first launch's agent followed the harness symlink and summarized the program's experiments (D-C10r-rulings-1 breach); eleven review rounds each found another readable history path.

**tmux driving traps.** Start tmux with the Claude env stripped (`env -u CLAUDECODE -u CLAUDE_CODE_* …`), else the nested claude refuses. A stray `zsh compinit: insecure directories…` line lands in the agent's input box at start — clear with **Ctrl-L** (user keybinding `chat:clearInput`) + a few BSpace; never Enter on it. Dim "suggested reply" ghost text looks like typed input in `capture-pane` — check with `-e` for `[2m`; Ctrl-E/Tab/→ accept it (don't). Esc interrupts the turn (kills helpers' wait); a message while it is "Waiting for background agent" may need a second Enter. The agent cannot `/exit` itself: `tmux kill-session -t '=name'` ([[tmux-kill-session-exact-name]]). If a session guard refuses an action, stop and use the legitimate permission channel; never hide the same action inside a script. Script files may improve command structure only for actions already authorized.
